# 5. 보안 알고리즘
## 5-1 보안 알고리즘
- 데이터를 주고받을 때, 생길 수 있는 문제는 크게 4가지이다.
  1. 도청
      - A가 B에게 메시지를 보냈을 때, X가 경로 중간에 훔쳐보는 것
  2. 위장
      - A가 B에게 보냈는데, X가 자신이 A라고 속이는 것
  3. 변조
      - A가 B에게 메시지를 보냈는데, X가 메시지를 바꿔서 보내는 것
  4. 사후 부인
      - B가 A에게 받았는데, A가 내가 보낸 것이 아니라고 부인하는 경우
      - 인터넷상의 계약에 문제가 생길 수 있음.
- 이걸 어떻게 막느냐?
  - 도청 -> 암호화
  - 위장 -> 인증 코드나 디지털 서명
  - 변조 -> 인증 코드나 디지털 서명
  - 사후 부인 -> 디지털 서명

## 5-2 암호의 기본
- 만약 같은 비밀키를 A와 B가 가지고 있다면
- 그 키를 이용해서 A가 암호화해서 메시지를 보내고
- B는 키를 이용해서 메시지를 복호화하면 중간에 키값을 모르는 제 3의 인물은 해독할 수 없음

## 5-3 해시 함수
- 주어진 데이터를 고정된 길이의 불규칙한 값으로 변환하는 함수
  - SHA-256 / SHA-512
- 어떤 길이의 데이터를 입력해도 출력되는 해시값의 데이터 길이는 일정함
  - 그렇기 때문에 완전히 다른 값을 입력해도 같은 값이 나올 수 있음 -> 충돌
    - 충돌이 나면?
- 같은 값을 입력하면 같은 해시값이 나옴
- 역산은 불가능
  - 사실 불가능은 아니고 완전탐색하면 찾을 수 있기는 함
  - 시간이 너무 오래걸려서 불가능이라고 하는 것
- 의외로 해쉬값을 만드는 계산은 가벼운 편

## 5-4 대칭키 암호 방식
- 같은 키값을 A, B가 가지고 있다가 암복호화시 사용하는 방법
  - 문제점은 키값이 노출되면 그냥 다 노출된다고 봐야함
- 만약 A와 B가 같은 키값을 가지고 있지 않다면?
  - 키값도 전달을 해주어야함
    - 결국 대칭키 암호 방식은 키값을 안전하게 전달해주는 방식이 필요한데 이 문제가 키 배송 문제라고 함.
    - 키 교환 프로토콜이나 공개키 암호 방식을 사용하는 방법으로 해결함

## 5-5 공개키 암호 방식
- 비대칭키 암호라고도 부름
  - 암호화에 사용되는 키 : 공개키
  - 복호화에 사용되는 키 : 비밀키
1. 데이터를 받는 쪽이 공개키와 비밀키를 만들고
2. 공개키를 A에게 전달
3. A는 B에게 전달받은 공개키를 사용하여 데이터를 암호화하고
4. A는 암호문을 B에게 보내고
5. B는 전달받은 암호문을 비밀키를 사용해 복호화
    - B는 원본 데이터 얻는데 성공
- 공개키는 전달하는 과정에서 노출될 수 있지만, 공개키로는 복호화가 불가능하기 때문에 문제 없음
- 하지만 공개키는 신뢰성 문제가 있음
  - 만약 B가 공개한 공개키를 X가 속이고 자신의 공개키로 A에게 전달되도록 하면?
  - 그러면 A는 X의 공개키로 암호화를 해서 보낼테고 X는 그 메시지 내용을 복호화해서 볼 수 있음
  - 그리고 X는 그 메시지 내용을 공개키로 암호화해서 B로 보낸다면?
  - B 입장에서도 누가 훔쳐봤다는 생각을 못하니까 그냥 아무문제 없다고 생각해버림
    - 이 공격이 중간자 공격
  - 그래서 디지털 서명을 통해서 공개키 증명을 한다고 함
- 다른 문제점은 성능 이슈
- 암호화 복호화에 시간이 걸리기 때문에 많은 데이터를 연속으로 주고받을때는 적합하지 않다고 함
