# 0. 알고리즘의 기본
## 0-1. 알고리즘이란?
- 알고리즘은 계산이나 작업을 수행하는 순서
- 비효율적인 알고리즘을 사용하면 시간이 어마어마하게 많이 든다.
- 즉 얼마나 적합한, 완성도 있는 알고리즘을 쓰느냐가 문제 해결에 중요함.

## 0-2. 계산 시간 측정 방법
- 알고리즘에 따라 계산 시간은 크게 달라지게 된다.
- 당연히 알고리즘 뿐만 아니라, Input의 양(10000개를 게산하는지, 10개를 계산하는지)도 계산 시간에 큰 영향을 미친다.
  - Input의 양이 1000배의 차이가 난다고 계산 시간도 1000배의 차이가 날까?
  - 그를 계산하기 위해 시간복잡도를 계산하는 것
- 시간복잡도는 계산식으로 구할 수 있는데, n이 무한이 되면 n의 제곱이 커지는 양이 크니, 다른 상수항 등은 계산에서 무시할 수 있다.
- `O`는 중요한 항 이외의 항은 무시한다는 의미이고 order(그런거였어? `O(n)`이 있으면,`오의 n`, `빅오 n` 라고 읽었는데)라고 읽는다.

# 1. 데이터 구조
## 1-1. 데이터 구조란?
- 전화번호부를 기록한다고 했을 때, 순서 없이 아무렇게나 넣는다면?
  - 어떤 사람을 찾을 때, 리스트를 전부 탐색해야하니 비효율적이고
- 이름순으로 넣는다면?
  - 찾을때, 이름을 보고 위치를 짐작할 수 있으니 탐색 시 효율적이고
  - 그렇지만, 중간에 데이터를 하나 삽입한다고 하면 뒤에 데이터를 다 이동시켜야하니 삽입 시 비효율적이다.
- 어떤 방법이 더 좋다고 말할수는 없다.
  - 데이터 삽입이 얼마나 빈번한지에 따라 다르다.

## 1-2. 리스트
- 리스트는 데이터를 일직선으로 연결한 데이터 구조이다.
- 데이터의 추가, 삭제는 쉽지만 원하는 데이터에 접근하는 시간은 오래 걸린다.
- 리스트의 노드의 포인터가 다음 노드를 가리킨다.
  - 그렇기 때문에, 메모리 공간에서 노드가 연속적으로 정렬되어 저장할 필요는 없다
  - 어차피 포인터만 믿으면 되니까
- 순차적으로 접근하다보니 탐색 시, 전체를 탐색해야한다.
- 기본적으로 링크드 리스트고, 마지막 노드의 포인터를 첫번째 노드로 연결하면 원형 리스트가 된다.
- 포인트를 앞 뒤로 연결하면, 양방향 리스트이다.

## 1-3. 배열
- 배열은 메모리내에서 데이터를 연속적으로 저장하는 데이터 구조이다.
- 인덱스를 통해 특정 메모리 공간에 바로 접근할 수 있도록 하니, 인덱스만 안다면 수정, 삭제, 삽입이 `O(1)`에 완료된다.
  - 물론 중간에 데이터 덮어씌우기 없이 삽입한다고하면 데이터를 뒤로 밀어야하니 그만큼 계산이 필요하다.
