# 4. 그래프
## 4-4 벨먼-포드 알고리즘
- 그래프의 최단 경로를 찾는 알고리즘
- 시작과 끝점이 지정되어 있고, 간선에 비용이 부여된 가중 그래프일 때 비용의 합이 가장 작은 길을 찾는 알고리즘
- 사이클의 가중치의 합이 음수일경우 벨먼 포드가 유용
  - 사이클이 음수임을 감지할 수 있기 때문
- 시간복잡도는 O(VE)
  - 다익스트라 알고리즘 보다는 약간 느리지만, 다익스트라 알고리즘은 전체 길을 최단 거리로 갱신하는 것은 아니니까..
- 간선의 정보만 가지고도 최단거리를 구할 수 있음
- 벨먼 포드 알고리즘의 동작은
  1. 출발 노드 설정
  2. 최단 거리 테이블 초기화(일종의 DP느낌)
  3. 간선의 개수 - 1만큼 반복하는데
     1. 전체 간선을 확인하고
     2. 각 간선을 거쳐 최단 거리로 갱신될수 있다면 갱신하고
  4. 만약 간선의 개수 - 1만큼 진행 후에 한번 더 돌렸는데도 값이 갱신되면 음수 사이클이 존재하는 것
     - 엇... 그럼 무조건 한번 그냥 더 도는게 낫긴하겠네


## 4-5 다익스트라 알고리즘
- 개인적으로 가장 천재적이라고 생각하는 알고리즘
  - 그리디하게 현재 상황에서 최적의 선택을 하는데, 그게 전체의 최적이 되는 알고리즘
- 기본적으로 현재 노드에서 가까운 노드부터 탐색 -> 즉 우선순위 큐를 사용함
  - 만약 우선순위 큐를 사용하지 않으면 O(V^2)이지만, 우선순위 큐를 사용하면 O(E + VlogV)
  - 음... 이 알고리즘에서 가장 문제가 되는 건, 노드의 시점에서 가장 가까운(최소값의 가중치를 갖는) 노드를 탐색하는 것
  - 그걸 탐색하는데 완전 탐색을 해야한다면 O(V^2) 이지만, 우선순위 큐로 항상 O(logV)로 최소 노드를 뽑아내줄수 있다면?
  - 그렇다면 거기에 간선의 수 만큼만 더해주면 되니까.. O(E + Vlog V)이긴 하네
- 현재 노드에서 가장 최소값을 찾아서 탐색을 진행하기 때문에, 음수인 간선이 있다면 무조건 선택이 됨.
  - 그리디 자체가 애초에 이전 최소값은 다 맞는 거라고 가정하고 다음으로 넘어왔으니..
  - 그러면 문제가 생기긴 하겠네
- 그리고 시작점 기준으로 모든 점까지의 거리를 최소값으로 갱신하는 거니까, 시작점이 아닌 다른 점에서 다른 점으로의 최소 거리는 알 수 없음.
  - 모든 노드를 시작점으로 넣고 돌리면 당연히 알 수 있겠지만.. 그럴바에는 다익스트라를 안쓰긴 하지

## 4-6 A star 알고리즘
- 다익스트라 알고리즘의 개선 버전
- 무조건 더 좋은 건 아니긴 하지만, 현실에서는 더 많이 사용함.
- 기본적인 아이디어 자체가 다익스트라랑 비슷함
  - 다익스트라는 그리디하게 간선의 가중치를 기준으로 최소값 위주로 먼저 챙겨서 확인하겠다는 아이디어이지만
  - 에이스타는 그 가중치 계산을 조금 다르게 할 수 있음.
    - 휴리스틱 함수를 어떻게 구현하느냐에 따라 달리지기 때문에, 결국 휴리스틱 함수의 퀄리티가 중요함
- 책에서는 다익스트라는 최단경로를 시작점에서 가까운 정점부터 탐색하기 때문에 도착지점에서 멀어지는 노드도 탐색하는 경우가 있다고 설명함
  - 결국 이렇게 되는 이유가 간선의 가중치에 대한 정보만 우선순위 큐에 넣기 때문
  - 만약, 출발점 근처는 도착점과 너무 머니까 가중치를 낮춰줄 수 있다면? 그 정보를 우선순위 큐에 포함시킬 수 있다면?
  - 출발점 근처의 정보는 우선순위큐에서 뒤로 밀려나게 되고 더 효율적인 알고리즘이 된다는 아이디어
  - 근데 그렇다면 어떻게? 간단하게 생각해보면 맨해튼 거리 구하는 공식을 휴리스틱 함수로 사용한다면 어느정도 가중치를 조절 할 수 있음
- 정말 놀랍게도 A, B, C, D, E 스타 알고리즘도 있음..
