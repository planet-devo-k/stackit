# 2. 정렬
## 2-1 정렬이란?
- 특정 기준으로 데이터를 나열하는 것

## 2-2 버블 정렬
- 오른쪽에서 시작하여 왼쪽 방향으로 인접한 두 숫자를 비교하여 교체하는 정렬
  - 왜 오른쪽이지? 내가 아는건 왼쪽부터 시작인데, 왼쪽도 되지 않나?
    - 아 보니까 그렇네, 오른쪽이든 왼쪽이든 상관이 없음
    - 단지 오른쪽부터 진행하면 가장 작은 값이 왼쪽에 확정이 되고
    - 왼쪽부터 진행하면 가장 큰 값이 오른쪽으로 확정이 되기 때문이구나
- O(n^2)의 시간 복잡도를 가지지만, 추가로 메모리 공간을 요구 하지 않는다는 장점이 있음.
  - 왜냐면, 그냥 그 배열 거기에서 옮기거나 할 필요 없이 진행하면 되니까

## 2-3 선택 정렬
- 내가 생각했을 떄, 가장 직관적인 정렬
  - 평소에 정리할때도 이런 정렬 방법을 많이 사용하는 듯 함.
- 최솟값 찾고, 맞는 위치로 옮기기를 계속 반복
- O(n^2)의 시간 복잡도를 가짐.

## 2-4 삽입 정렬
- 가장 왼쪽 숫자를 정렬된것으로 치고 그 숫자를 기준으로 왼쪽 오른쪽에 삽입을 해주며 정렬을 진행함.
  - 밀어내는 작업도 필요함
    - 삽입할때 뒤의 인덱스의 원소를 한칸씩 다 밀어내주어야하니까 연결리스트로 구현하면 조금 더 빠를려나? 싶지만 어차피 넣을 자리를 탐색할때 순회해야하므로 배열이나 거기서 거기라고 함.
      - 하긴.. 순회하는건 배열이 더 싸니까
- O(n^2)의 시간 복잡도를 가짐.

## 2-5 힙 정렬
- 힙 자료구조를 이용한 정렬
- 힙 자료구조를 일단 구현만 해놓으면, 가장 작은 값을 먼저 빼도록 되어있을테니 모든 값을 다 빼면 정렬이 완료됨
- O(n log n)의 시간복잡도를 가짐.
- 별도의 메모리 공간이 필요함. (힙에 넣어야하니까)

## 2-6 병합 정렬
- 재귀로 구현하는 것으로 알고있음
- 쪼갤 수 없을때까지 쪼개고 합치면서 비교해서 정렬하는 구조
- O(log n)의 시간복잡도

## 2-7 퀵 정렬
- 피봇을 정해서 그 피봇 기준으로 작은 그룹, 큰 그룹으로 일단 나누고
- 그걸 계속 반복해서 정렬하는 방식
- 피봇의 위치는 무조건 확정됨
- 근데 피봇을 잘 골라야 정렬횟수가 줄어들 것 같은데..
  - 아 그러네 피봇을 만약 운안좋게 맨 앞만 계속 고르게 되면, 사실상 하나씩 위치를 정하는 거니까 최악의 경우 O(n^2)이 되네
