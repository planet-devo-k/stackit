# 5-1 보안과 알고리즘

1. 도청
    - A가 B에게 메시지를 보냈을 때 X가 경로 도중에 메시지 내용을 훔쳐보는 것
    - 인가되지 않은 사용자가 정보의 내용을 알 수 없게 하는 **기밀성** 위배
    - 이를 해결하기 위해 **암호화** 기법 사용
2. 위장
    - A가 B에게 메시지를 보냈는 데 X가 경로 도중에 자신이 A,B인척 하는 것
    - X가 A나 B인 척 속이는 행위는 신원 검증을 무력화 한것이므로 **인증** 위배
    - 이를 해결하기 위해 **메시지 인증코드** 사용
3. 변조
    - A가 B에게 메시지를 보냈지만 경로 도중에 X에 의해 메시지가 바뀌는 것
    - 데이터의 정확성과 신뢰성을 뜻하는 **무결성** 위배
    - 이를 해결하기 위해 **메시지 인증코드 혹은 디지털 서명** 사용
4. 사후 부인
    - B가 A에게 메시지를 받았는데 A가 악의적으로 자신이 보낸 메시지가 아니라고 하는 것
    - 이를 해결하기 위해 **디지털 서명** 사용

# 5-2 암호의 기본

- 암호문
    - 비밀 데이터는 제 3자가 훔쳐볼 가능성이 있기 때문에 암호화해서 전송 , 이를 **암호문**
- 복호화
    - 암호문을 원본 데이터로 되돌리는 것을 **복호화**

# 5-3 해시 함수

- 해시값
    - 데이터를 해시 함수에 넣어 출력되는 불규칙한 값 -> **해시값**
    - 특징
        1. 출력하는 데이터의 길이가 일정
        2. 같은 입력에 대한 출력은 언제가 같음
        3. 비슷한 데이터가 입력된다하더라도 완전 다른 출력값
        4. 다른 입력이라도 동일한 해시값이 되는 경우가 발생 -> **해시 충돌**
        5. 암호문과 달리 해시값에서 원본 데이터를 역산하는 건 사실상 불가능 , 단방향
        6. 해시값을 구하는 계산이 빠름
    - 예시
        - 비밀번호 서버 보관

# 5-4 대칭키 암호 방식

- 대칭키 암호화
    - 암호화와 복호화에 동일한 키를 사용하는 암호 방식
    - 알고리즘
        - 시저 암호, AES, DES, 원타임 패드
    - 문제점
        - 암호화와 복호화에 같은 키를 쓰기 때문에 키가 유출되면 복호화 가능
        - 키를 안전하게 전달하는 키 배송 문제
        - 키 교환 프로토콜이나 공개키 암호 방식 사용

# 5-5 공개키 암호 방식

- 비대칭키 암호화 (공개키 암호화)
    - 개념
        - 암호화와 복호화에 서로 다른 키를 사용하는 것
        - 암호화에 사용되는 키 => **공개키**
        - 복호화에 사용되는 키 => **비밀키**
        - 불특정 다수 간 통신에 활용하기 쉬움
    - 동작과정
        - 데이터를 수신하는 쪽(B)에서 공개키, 비밀키 모두 생성
        - B가 A에게 공개키만 전달
        - A는 공개키를 이용해서 평문을 암호화해서 전달
        - B는 암호문을 비밀키를 이용해서 복호화
    - 알고리즘
        - RSA, 타원 곡선 암호
    - 문제점
        1. 공개키를 전달하는 과정에서 탈취할 수 있음, X가 자신이 만든 공개키,
            - 비밀키로 암호화하게 설정하고 복호화 => **중간자 공격**
            - 이를 해결하기 위해 디지털 서명 사용
        2. 암호화 및 복호화에 시간이 많이 듬 => **하이브리드 암호 방식** 사용
