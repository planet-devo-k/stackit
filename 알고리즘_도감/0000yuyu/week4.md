# 3-1 선형 탐색

- 배열에서 데이터를 찾는 알고리즘
- 데이터가 순서 없이 나열된 경우에도 적용 가능
- 데이터의 처음부터 끝까지 비교하는 방식 최악의 경우 O(n)

# 3-2 이진 탐색

- 배열에서 데이터를 찾는 알고리즘
- 데이터가 정렬된 경우에만 적용 가능
- 탐색을 할 때마다 검색 범위가 줄어 듬 O(log n)

### 선형 탐색 vs 정렬 후 이진 탐색

- 데이터가 정렬되어 있지 않은 경우, 단순히 한 번만 탐색한다면 순차적으로 비교하는 선형 탐색을 사용하는 것이 직관적이고 단순
- 하지만 대규모 데이터에서 여러 번의 탐색이 필요하다면, 데이터를 먼저 정렬한 후 이진 탐색을 수행하는 것이 일반적으로 더 빠르고 효율적입니다.
- 데이터의 크기 n이 작을 때는 정렬 비용이 더 클 수 있어 선형 탐색이 유리할 수 있지만, 정렬된 상태라면 이진 탐색의 시간 복잡도는 𝑂(log 𝑛)으로 매우 낮아짐
- 데이터 셋이 매우 커서 정렬에 드는 비용이 탐색 자체의 이득보다 크다면, 선형 탐색이 더 빠를 수 있음
- 데이터가 매우 작은 임계값 이하거나 연결 리스트 형태로 저장되어 있다면 선형 탐색이 더 적합함

# 4-1 그래프란?

- 몇개의 정점이 간선으로 연결되어 있는 것

### 가중 그래프

- 간선에 무게나 비용이 할당된 그래프

### 방향성 그래프

- 간선에 방향을 부여한 그래프 (<-> 무방향 그래프)

### 인접 리스트

- 인접 리스트는 각 정점에 대해 해당 정점과 직접 연결된 정점들을 원소로 가지는 리스트의 배열 또는 리스트의 리스트 형태
- 특정 정점 𝑖에 연결된 노드들은 adj라는 리스트 안에 순차적으로 저장되어 관리
- 이러한 연결 방식은 노드 간의 관계를 직관적으로 표현하며, 그래프의 핵심적인 구현 방법 중 하나
- 각 정점에 대한 메인 배열을 만들고, 각 인덱스에 인접 정점들을 연결 리스트(Linked List)로 이어 붙이는 가장 일반적인 방식

###### 무방향 그래프

- 무방향 그래프에서는 두 정점 a와 𝑏사이의 간선이 한 번씩, 총 두 번 저장
- 즉, a 정점의 인접 리스트에 𝑏를 추가하고, 동시에 b 정점의 인접 리스트에도 a를 추가하는 과정이 필요

###### 방향성 그래프

- 방향성 그래프에서는 간선의 시작 정점에 해당하는 리스트에만 도착 정점의 정보를 저장하여 방향성을 유지합니다.

# 4-2 너비 우선 탐색 (BFS)

- 그래프를 탐색하는 알고리즘
- 시작노드에서 인접한 노드들을 먼저 모두 방문하여 옆으로 넓게 탐색하는 방식
- 방문한 노드들을 순서대로 꺼내기 위해 큐라는 자료구조 사용
- 노드의 수 V, 간선의 수 E 일때, O(V+E)

# 4-3 깊이 우선 탐색 (DFS)

- 그래프를 탐색하는 알고리즘
- 그래프에서 한 노드를 선택한 후, 다음 분기로 넘어가기 전에 해당 분기를 완벽하게 탐색하는 방식
- 가능한 깊게 탐색하다가 더 이상 갈 곳이 없으면 이전 노드로 돌아와 다른 경로를 찾는 과정을 반복
- 주로 스택이나 재귀 함수 사용
