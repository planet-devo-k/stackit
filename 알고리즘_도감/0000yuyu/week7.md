# 5-6 하이브리드 암호 방식

### 문제

- 대칭키 암호 방식 : 키 배송 문제 , 비대칭키(공개키) 암호 방식 : 암호화와 복호화 처리 속도가 느리다는 문제

### 해결

- 대칭키 암호 방식과 비대칭키 암호 방식을 조합하여 단점 보완
    - 데이터를 암호화 할 땐 처리 속도가 빠른 대칭키 암호 방식 사용, 이때 키는 공개 키 암호 방식으로 주고 받음
    - A는 키를 이용해 암호화하고 그 키 자체는 B의 공개키를 사용해 암호화하며 B는 자신의 비밀키를 이용해 키를 획득해 데이터를 복호화한다.

### 사용

- 인터넷에서 안전하게 정보를 주고 받기 위한 프로토콜인 SSL에 사용

# 5-7 디피 헬만 키 교환법

### 정의

- 두 사람이 안전하게 키를 교환하는 기법
- 공개해도 괜찮은 정보를 서로 교환함으로써 두 사람이 키를 교환할 수 있는 방법
- 실제로는 교환하는 것이 아니라 생성하는 것이므로, 디피-헬먼 키 합의라고 부르기도 함

### 과정

1. A가 B에게 P를 전송
2. A의 SA와 B의 SB는 타인에게 알려지지 않도록 관리하여 준비
3. A와 B는 각각 SA,SB를 가지고 P를 이용해 새로운 키를 합성합니다. (P-SA,P-SB)
4. P-SA,P-SB를 서로 전달한다.
5. A와 B는 자신의 키(SA,SB)를 자신이 전달 받은 키(P-SA,P-SB)를 합성한다.
6. A와 B는 모두 SA-P-SB, SB-P-SA와 같은 동일한 키를 얻어 암호화, 복호화 키를 사용하게 된다.

### 문제

- P,P-SA,P-SB를 교환하는 과정에서 제삼자(X)가 보거나 수정할 수 있다.
    - 키는 분해할 수 없기 때문에 비밀키는 얻지 못함
    - 비밀키(SA,SB)를 알지 못하기 때문에 복호화는 불가
    - 아무도 갈취할 수 없다는 것으로 안전은 하지만 악의적으로 수정한다면 어떻게 될까?
        - 메시지 인증 코드를 사용

### 실제 동작 과정

- 맨 처음 만들어지는 P = P,G 두 정수로 표현
- G는 소수 P에 대한 생성자(원시근)라고 부르는 수에서 하나를 선택
- A와 B는 P,G를 주고 받음
- A와 B가 준비하는 비밀키는 각각 P-2보다 작아야 함

# 5-8 메시지 인증 코드

### 정의

- 암호문이라도 도중에 내용이 변조되어 다른 내용으로 복호화됨으로써 오해가 생기는 것을 막아주는 것
- 인증과 변조 검출이라는 두 가지 기능 제공

### 동작 과정

- A와 B는 서로 암호문과 키를 교환합니다.
- A는 암호문과 키를 사용하여 어떤 값 (메시지 인증 코드,Mac)을 만들어서 전송합니다.
- A와 마찬가지로 B도 암호문과 키를 사용하여 MAC을 만듭니다.
- A가 생성한 MAC과 B가 생성한 MAC이 일치하는 지 확인합니다.
    - 이때 X가 변조하는 경우 해시값이 다르게 나옵니다.

### 문제

- A와 B가 MAC을 주고 받을 때 A,B가 모두 악의적으로 서로가 날조한 메시지라고 주장하는 것이 가능해서
- 누가 보냈는지 모름
    - 전자서명에서 해결

# 5-9 전자 서명(디지털 서명)

### 정의

- 메시지 인증 코드가 제공하는 인증과 변조 검출이라는 두 가지 기능 뿐만 아니라 사후 부인도 방지하는 매커니즘
- 디지털 서명 구조는 전송자만 작성할 수 있는 디지털 서명이라는 데이터를 사용하여 메시지 작성자를 특정
- 비대칭 암호 방식 사용

### 원리

1. A는 B에게 메시지를 보낼 때 디지털 서명을 만들어서 전송합니다.
2. B는 디지털 서명을 통해 보낸 사람이 A라는 것을 보증합니다. 하지만 B는 디지털 서명을 만들 순 없습니다.

### 동작 과정

1. A가 보내고 싶은 메시지와 비밀키, 공개키를 준비합니다.
    - 메시지를 보내는 쪽에서 비밀키와 공개키를 준비한다는 점이 공개키 암호 방식과 다름
2. A가 B에게 공개키를 전달
3. A는 비밀키를 사용하여 메시지를 암호화 -> 디지털 서명
4. A는 B에게 메시지와 서명을 전송
5. B는 공개키를 사용하여 암호문을 복호화
6. B는 복호화한 메시지와 받은 메시지가 일치하는 지 확인

### 문제

- 공개키를 사용해서 복호화하는 거면 누구가 복호화할 수 있는 암호문?
    - 암호문의 작성자가 비밀키를 가진 A임이 보장되는 구조
- 공개키를 보장하지 못함

# 5-10 전자 인증서

### 정의

- 공개키가 자신의 것이라는 것을 입증하기 위한 것

### 동작 과정

- A는 인증 기관 (CA)에 공개키가 자신의 것이라는 인증서 발행을 요청
- 인증 기관에서 A의 데이터, 공개키와 인증 기관의 비밀키를 이용해 디지털 서명 작성
- 인증기관이 A에게 파일 전송
- A는 B에게 공개키 대신 디지털 인증서를 B에게 보냄
- B는 전달받은 인증서에 쓰인 메일 주소가 A의 것임을 확인
- B는 인증기관의 공개키를 통해 인증서 내 서명이 인증 기관의 것인지 검증

# 전체 통신 과정

- 이 모든 기술은 따로 노는 것이 아니라 하나의 파이프라인으로 연결됨

1. 신원 확인 : 전자 서명서를 통해 A와 B가 서로 누구인지 확인
2. 키 교환 : 디피-헬만 알고리즘을 통해 안전하게 대칭키를 생성
    - 이때, 매 세션마다 새로운 키 생성
3. 암호화 통신 : 속도가 빠른 대칭키 암호를 사용해 실제 데이터를 암호화하여 주고 받음
4. 무결성 유지 : 중간에 누군가 데이터를 변조했는지 MAC을 통해 실시간으로 체크

# 실제 채택 방식

- HTTPS
    1. 인증 : SSL/TLS 인증서를 통해 서버의 신원 확인 (SSL 핸드셰이크)
    2. 키 교환 : 주로 ECDHE(타원 곡선 디피-헬만) 알고리즘을 사용
        - 이를 통해 매번 통신 시마다 대칭키를 새로 생성하여,
        - 나중에 서버의 비밀키가 갈취되더라도 과거의 통신 내용은 복호화할 수 없게 함
    3. 암호화 : AES 같은 매우 빠른 대칭키 암호화 방식 사용
    4. 무결성 : TLS 1.3에서는 MAC을 포함한 인증 암호화 방식을 사용하여 변조를 방지
