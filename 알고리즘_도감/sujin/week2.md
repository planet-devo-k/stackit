# 1-4. 스택

> 데이터를 한 열로 저장하지만, 서류를 쌓아올릴 때처럼 마지막에 추가한 데이터에만 접근할 수 있음. (Last In First Out; LIFO)

- 푸시 : 스택에 데이터를 넣는 작업
- 팝: 스택에서 데이터를 꺼내는 작업

### 활용사례

- 항상 최신 데이터에 접근해야할 때 유용함

# 1-5 큐

> 데이터를 한열로 저장한다. 스택과 비슷하지만 큐는 추가하는 쪽과 삭제하는 쪽이 반대이며 대기 행렬이라고도 불림.(First In First Out; FIFO)

- 인큐: 큐에 데이터를 추가하는 작업
- 디큐: 큐에서 데이터를 꺼내는 작업

# 1-6. 해시 테이블

> 해시 함수를 활용해 만든 데이터 구조. 데이터를 효율적으로 검색할 수 있음.

- 해시 테이블은 키와 값을 하나의 짝으로 저장하는 데이터 구조.
- 선형 탐색 : 특정한 키의 값을 알고 싶을때 앞에서부터 차례대로 확인하는 것.
  - 데이터 양에 비례하여 계산시간이 늘어남. 데이터 타맥 시 시간이 오래걸리므로 배열에 키, 값 데이터를 저장하는 것은 그다지 효율적이지 않음
  ⇒ 해시 테이블이 이 문제를 해결해줌
- 해시 테이블은 해시 함수를 사용하여 배열 내 데이터에 빠르게 접근할 수 있음. 그리고 해시값이 충돌할 때는 리스트를 사용하기 때문에 저장할 데이터 수가 정해져 있지 않더라도 유연하게 대응할 수 있음
- 해시테이블에서 사용하는 배열 크기가 너무 작으면 충돌이 많아져 선형 탐색이 많이 발생
- 분리 연쇄법(체이닝) : 데이터를 배열에 저장하다가 충돌이 발생하면 리스트를 사용해 기존 데이터 뒤에 연결하는 것
- 개방 주소법: 충돌이 발생하면 다음공간을 찾아 저장.

# 1-7. 힙

> 그래프의 트리 구조 중 하나로 우선순위 큐를 구현할떄 사용됨.

- 우선순위 큐: 데이터를 자유롭게 추가할 수 있지만 꺼낼때는 항상 가장 작은 데이터를 꺼냄
- 노드: 힙을 비롯한 트리구조에서 각 정점을 노드라고 함

## 규칙

- 각 노드는 자식 노드를 최대 2개 가질 수 있음
- 노드는 위에서 부터 채우지며 같은 층에서는 왼쪽부터 채워짐
- 데이터를 저장할 때 자식노드의 값이 반드시 부모 노드의 값보다 커야함. 따라서 맨 위 노드는 가장 작은 값
- 데이터를 추가할떄
  - 데이터를 저장할 떄의 규칙을 지키기 위해 맨 아래층 왼쪽에 데이터를 추가. 맨 아래층에 더이상 추가할 공간이 없으면 새로은 층을 만들고 역시 맨 왼쪽에 추가
- 데이터를 꺼낼 떄: 제일 위에있는 데이터를 꺼냄.

# 1-8. 이진탐색트리

> 그래프의 트리구조로 각 노드에 데이터가 저장됨

## 특징

- 각 노드의 값은 왼쪽 가지에 있는 노드들의 값보다 큼
- 각 노드의 값은 오른쪽 가지에 있는 노드들의 값보다 작음
