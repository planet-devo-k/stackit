# 5-1. 보안 알고리즘

## 인터넷에 필수 불가결한 보안

인터넷을 경유하여 데이터를 주고받을 때, 데이터는 다양한 네트워크와 기기를 경유하여 상대에게 전달. 이때
악의를 품은 사람이 관리하는 기기를 경유하면 도청당할 위험이 있음
따라서 인터넷을 안전하게 사용하기 위해서는 보안 기술이 반드시 필요함.

## 데이터를 주고받을 떄 발생하는 4가지 문제

- 도청
  A가 B에게 메세지를 보냈을 떄 X가 경로 도중에 메세지를 훔쳐보는것
- 위장
  A가 B에게 메세지를 보냈는데 X가 B라고 속이는것. 혹은 X가 A라고 속이는것
- 변조
  A가 B에게 메세지를 확실히 보냈지만 경로 도중에 X에 의해 메시지가 바뀌는것
- 사후부인
  B가 A에게 메세지를 받았는데 메세지를 보낸 A가 나중에 악의적으로 자기가 보내지 않았다고 부인하는 것

## 문제에 대한 보안 기술

- 도청 : 암호화
- 위장 : 메세지 인증코드, 디지털 서명 기술
- 변조 : 메세지 인증코드, 디지털 서명기술
- 사후부인 : 디지털 서명 기술

# 5-2 암호의 기본

- 암호문

1. A가 B에게 데이터를 보내려고 함
2. 악의를 가진 제삼자가 데이터를 훔쳐볼 가능성이 있음.
3. 따라서 비밀 데이터는 암호화해서 전송해야 함(암호문)
4. 암호문을 B에게 전송하면 B는 A에게 받은 암호문의 암호를 해독해서 원본데이터를 얻음(복호화)

- 암호화란 데이터에 어떤 연산을 적용해서 컴퓨터가 해석할 수 없는 숫자로 바꾸는 것을 의미
  암호화의 수치 계산은 키를 사용하는데, 키 역시 숫자로 만들어짐.

# 5-3 해시 함수

데이터를 해시함수에 입력하면 고정된 길이의 불규칙한 값을 출력. 출력된 불규칙한 값을 해시값이라고 함.

- 해시함수의 특징
  1. 출력하는 값의 데이터 길이가 일정. 매우 큰 데이터를 입력해도 출력되는 해시값의 데이터의 길이는 일정
  2. 같은 입력에 대한 출력은 언제나 같음
  3. 비슷한 데이터가 입력된다 해도 데이터가 1비트라도 다르다면 출력 결과는 크게 달라짐. 비슷한 데이터를 입력한다고 해서
     해시값도 비슷한 값이 나오지는 않음
  4. 완전히 다른 데이터를 입력해도 동일한 해시값이 되는 경우가 적은 확률이지만 발생(해시 충돌)
  5. 해시값에서 원본데이터를 역산하는건 사실상 불가능. 데이터의 입력과 출력은 단방향이며, 이점은 암호화와 다른 부분.
  6. 해시값을 구하는 계산이 비교적 용이.
- 대표적인 알고리즘
  MD5, SHA-1, SHA-2 등이 있으며 SHA-2를 사용하는 것이 일반적.

# 5-4 대칭키 암호 방식

암호화와 복호화에 동일한 키를 사용하는 암호 방식

- 시저 암호, AES, DES, 원타임 패드 등이 있으며 현재는 AES가 주로 사용됨

1. A가 B에게 인터넷을 통해 데이터를 전송하려고 함.
2. 훔쳐볼 가능성이 있기 때문에 비밀정보는 암호화 해서 보내야 함.
3. A는 키를 사용해 데이터를 암호화하여 암호문으로 바꿈.
4. A는 B에게 암호문을 전송
5. B는 A에게 받은 암호문을 동일한 키를 사용해 복호화하고, B는 원래 데이터를 얻음.

- 대칭키 암호화 방식의 문제점
  - 여기서 B가 A에게 암호문을 전달받았을 때, X가 훔쳐봤을 가능성이 있음.
  - B가 암호화에 사용된 키를 모른다고 가정하면 A는 B에게 키를 반드시 전달해야함. 그래서 A는 인터넷으로 키를 전달.
  - 하지만 이 과정에서 X가 훔쳐볼 가능성이 있음. (키 배송 문제)
  - 키 배송 문제를 해결하려면 키 교환 프로토콜이나 공개키 암호 방식을 사용해 해결할 수 있음.

# 5-5 공개키 암호 방식

암호화와 복호화에 서로 다른 키를 사용하는 것(비대칭키 암호). 공개키(암호화에 사용), 비밀키(복호화에 사용)

- RSA 암호, 타원 곡선 암호 등이 있으며 현재는 RSA 암호를 주로 사용.
