# 5-6 하이브리드 암호 방식

대칭 키 암호방식에서의 키 배송문제와 공개키 암호방식에서의 암호화/복호화 처리속도가 느린 문제를
보완하는 방식

1. 데이터를 암호화할 떄 처리 속도가 빠른 대칭키 암호 방식을 사용. 이때 대칭키 암호 방식에서 사용하는
   키는 키배송이 필요하지 않은 공개키 암호 방식을 사용하여 주고받음
2. A가 B에게 인터넷으로 데이터를 보내려고 함.
3. 데이터는 처리속도가 빠른 대칭키 암호 방식을 사용하여 암호화. 암호화에 사용된 키는 복호화에 필요하기
   때문에 A는 B에게 키를 전송해야 함.
4. 키는 공개키 암호 방식으로 암호화하여 안전하게 B에게 보낼 수 있음. 수신자인 B가 공개키와 비밀키를 작성
5. B는 A에게 공개키를 전송
6. A는 B에게 받은 공개키를 사용하여 대칭키 암호방식에 사용할 키를 암호화
7. A는 B에게 암호화한 키를 전송
8. B는 암호화된 키를 비밀키를 사용하여 복호화
9. 이렇게 A는 B에게 대칭키 암호 방식에서 사용할 키를 안전하게 전달할 수 있음
10. 이제 이 키를 사용해 암호화된 데이터를 보내면 됨. 데이터를 암호화 할때는 처리속도가 빠른 대칭키 암호방식을 사용.

- 하이브리드 암호 방식은 SSL에서 사용됨. SSL은 현재 버전 업되어 TLS가 정식 명칭.

# 5-7 디피-헬먼 키 교환법

두 사람이 안전하게 키를 교환하는 기법. 두 사람이 공유할 비밀의 수를 공개된 숫자와의 연산에 섞어 넣음으로써
두 사람 사이의 대칭키를 안전하게 교환

1. A와 B가 키를 교환하려고 함.
2. 두 키를 합성하는 특별한 방법이 있다고 가정. 그 합성 방법으로 P와 S를 합성하면 P와 S를 성분으로 구성된 새로운 키 P-S
   가 만들어짐.
3. 이 합성 방법에는 세가지 특징이 있음'
   1. P와 이를 사용하여 합성된 P-S가 있더라도 S를 추출하는 것은 불가능
   2. 키를 합성해 만든 키도 새로운 키의 합성 요소로 사용할 수 있음.
   3. 키의 합성 결과는 순서와 상관없이 어떤 키를 사용했는지에 따름

      ex) B, C를 합성해 B-C를 만들고 A와 B-C를 합성해 A-B-C를 만듦. 그리고 A와 C를 합성해 A-C를 만들고 B와 A-C를 합성해서 B-A-C를 만들었을때, A-B-C와 B-A-C는 동일한 키.
4. 이 합성 방법을 이용해 키를 교환. A가 키 P를 준비.
5. A가 B에게 P를 전송
6. A와 B는 비밀키 SA와 SB를 준비
7. A는 P와 비밀키 SA를 바탕으로 새로운키 P-SA를 합성
8. 마찬가지로 B도 P와 비밀키 SB를 사용해 새로운 키 P-SB를 합성
9. A가 B에게 P-SA를 전송. 마찬가지로 B도 A에게 P-SB를 전송
10. A는 자신의 비밀키 SA와 B에게 받은 키 P-SB를 합성해서 새로운 키 SA-P-SB를 만듦
11. 마찬가지로 B도 자신의 비밀키 SB와 A에게 받은 키 P-SA를 합성해 새로운 키 P-SA-SB를 만듬. A도 B도 키 P-SA-SB를 얻게됨. 이키를 암호키, 복호화키로 사용
12. 여기서 P, P-SA, P-SB는 인터넷을 통해 전송되기 떄문에 악의를 가진 제삼자 X가 훔쳐볼 수 있음.
13. 하지만 X가 얻은 키로는 P-SA-SB를 합성할 수 없음. 따라서 X는 P-SA-SB를 만들 수 없고, 이 교환 방법은 안전.

- 키 교환 방식을 수식으로 표현하기
  - 맨 처음 만들어지는 공개 가능한 키 P는 수식상 P,G라는 두 정수로 표현. P는 굉항히 큰 소수이며 G는 소수 P에 대한 생성자(혹은 원시근)라고 부르는 수에서 하나를 선택
  1. 먼저 A가 소수 P와 생성자 G를 준비. 이 값들은 제삼자에게 노출되어도 문제가 되지 않음
  2. A가 소수 P와 생성자 G를 B에게 전송
  3. 이어서 A와 B는 각각 비밀값 X와 Y를 준비. 비밀값 X와 Y는 P-2보다 작아야함.
  4. A와 B는 각각 ‘(G의 비밀값(X 또는 Y)제곱) mod P’를 계산. mod연산은 나눗셈의 나머지를 구하는 연산. ‘G mod P’는 G를 P로 나눴을 떄으 ㅣ나머지. 이 계산이 개념상 합성에 해당
  5. A와 B는 계산결과를 서로에게 전송
  6. A와 B는 상대로부터 받은 숫자를 자신의 비밀값으로 제곱하고 mod P를 계산. 이 계산 결과는 A와 B 모두 같은 값을 얻음
  7. X가 통신을 훔쳐보고 얻은 숫자로는 A와 B가 공유한 숫자를 계산할 수 없음. 또한 비밀값 X와 Y를 구하는 것도 불가능
- 소수 P, 생성자 G, G의 비밀값(X) 제곱 mod P에서 X를 구하는 문제는 이산대수 문제라고 부르며, 아직 효율적인 해법이 발견되지 않음

# 5-8 메시지 인증 코드

메세지 인증 코드는 인증과 변조 검출이라는 두 가지 기능을 제공. 암호문이라도 도중에 내용이 변경되어 다른 내용으로 복호화 됨으로써 오해가 발생할 위험이 있음. 이를 막아주는것이 메시지 인증코드

1. A가 B에게 상품을 구매하기 위해 상품 번호를 의미하는 ‘abc’를 보내려고 함
2. 여기서 A가 메시지를 암호화. 암호화할 때는 대칭키 암호 방식을 사용. A는 안전한 방법으로 B에게 키를 전달.
3. A는 공유한 키를 사용하여 메시지를 암호문으로 만듬
4. A는 암호문을 B에게 전송하고 B는 전달받은 암호문을 복호화. B는 메시지인 상품 번호 ‘abc’를 취득
5. 지금까지는 문제가 발생하지 않는 경우지만 다음과 같은 일이 발생할 수 있음
6. A가 B에게 전송하는 암호문을 악의를 가진 X가 통신 도중에 변조했더라도, 암호문을 수령한 B는 이것이 변조된 것인지 알 수 없음.
7. B가 변조된 암호문을 복호화하면 메세지가 ‘xyz’로 바뀌어 있습니다.
8. B는 ‘xyz’가 주문된 상품번호라고 믿고 A에게 잘못된 상품을 발송
9. 메시지 인증 코드를 사용하면 이러한 메시지 변조를 감지할 수 있음.
10. A는 메시지 인증 코드를 작성하기 위한 키를 만들어 안전한 방법으로 B에게 키를 전송
11. 이어서 A는 암호문과 키를 사용하여 어떤 값을 만듬. 여기서는 7f05라는 값이 만들어졌다고 가정. 이 키와 암호문을 조합하여 만든 값을 메시지 인증코드라고 부름(MAC; Message Authenfication Code).
12. A는 B에게 자신이 만든 MAC을 암호문과 함께 전송
13. A와 마찬가지로 B도 암호문과 키를 사용하여 MAC을 만듦. B가 스스로 계산한 7f05와 A에게 전달받은 7f05가 일치하는 것을 확인
14. 이제 암호문을 위한 키를 사용하여 복호화. 그러면 A가 주문한 상품인 ‘abc’라는 메세지를 무사히 획득

- 만약 악의를 가진 X가 통신 도중에 암호문을 변조하는 경우

1. A가 B에게 보내는 암호문과 MAC중 암호문을 X가 변조했다고 가정
2. B가 암호문으로 MAC을 계산하면 b85c가 나옴. A에게 받은 MAC 7f05와 일치하지 않음
3. 이로써 B는 암호문이나 MAC, 혹은 둘다 변조되었을 가능성이 있음을 알게됨. B는 A에게 받은 암호문과 MAC을 파기하고, A에게 다시 전송해달라고 요청

- 한계점
  - 메시지 인증 코드에서는 A와 B 양쪽 다 메시지를 암호화해서 MAC을 계산할 수 있음. ⇒ 메시지를 작성한 것이 A인지 B인지 증명할 수 없음
  - 이를 해결하기 위한 것이 디지털 서명

# 5-9 디지털 서명

메시지 인증 코드가 제공하는 인증과 변조 검출이라는 두가지 기능 뿐 아니라 사후 부인도 방지하는 메커니즘. 메시지 인증코드는 대칭키를 사용하는 구조이기 때문에 키를 가진 수신자도 메시지의 전송자일 가능성이 있어 사후 부인 문제를 막을 수 없음. 그러나 디지털 서명 구조는 전송자만 작성할 수 있는 디지털 서명이라는 데이터를 사용하여 메시지 작성자를 특정

- 특징

1. A가 B에게 메시지를 보내려고 함
2. 이떄 디지털 서명을 부여. 디지털 서명은 A만 만들 수 있음
3. A의 디지털 서명이 부여된 메시지가 전송된 경우 보낸 사람이 A인 것이 보증
4. B는 디지털 서명의 정당성을 검즐할 수 있지만 디지털 서명을 만들수는 없음

- 만드는법

1. 디지털 서명 작성에는 공개키 암호 방식을 사용. 공개 키 암호방식에서는 암호화에 공개키를 사용했고 복호화에 비밀키를 사용하며, 공개키를 사용해 누구라도 데이터를 암호화할 수 있지만 비밀키를 가진 사람만 복호화할 수 있지만 디지털 서명에서는 이 흐름이 반대.
2. A가 보낼 메시지와 비밀키, 공개키를 준비.(보내는 쪽에서 비밀키와 공개키를 준비하는것이 차이)
3. A가 B에게 공개키를 전달
4. A는 비밀키를 사용하여 메시지를 암호화. 이 메시지를 암호화 한것이 디지털 서명
5. A는 B에게 메시지와 서명을 전송
6. B는 공개키를 사용하여 암호문(서명)을 복호화
7. B는 복호화한 메시지와 받은 메시지가 일치하는 지 확인.

⇒ 비밀키를 가진 A만 암호화 할 수 있지만 누구나 공개키를 사용해 복호화 할 수 있는 암호문이 작성됨 ⇒ 암호문의 작성자는 A라는 것이 보증된 구조. B가 A의 서명을 만들수도 없기 때문에 사후 부인 방지 가능

# 5-10 디지털 인증서

공개키 암호화 방식이나 디지털 서명에는 공개키가 상대의 것인지 보증되지 않는 문제가 있음. 디지털 인증서를 사용하면 공개키의 정당성을 보장할 수 있음

1. A는 공개키 PA와 비밀키 SA를 쌍으로 가지고 있으며 공개키를 B에게 보내려고 함
2. A는 먼저 인증기관에 공개키가 자신의 것이라는 인증서 발행을 요청
3. 인증 기관은 자체적으로 준비한 공개키 PC와 비밀키 SC를 보유하고 있음
4. A는 공개키 PA와 메일 주소를 포함한 개인 정보를 인증 기관에 보냄
5. 인증 기관은 전송된 정보가 틀림없이 A의 것임을 확인. 확인이 완료되면 인증 기관의 비밀키 SC를 사용해 A의 데이터를 바탕으로 디지털 서명을 작성
6. 인증 기관은 작성한 디지털 서명과 데이터를 하나의 파일로 만들고 인증기관은 A에게 파일을 전송
7. 이 파일이 A의 디지털 인증서가 됨. A는 공개키 대신 디지털 인증서를 B에게 보냄
8. B는 전달받은 인증서에 쓰인 메일주소가 A의 것임을 확인. 이어서 B는 인증기관의 공개키를 가져옴
9. B는 인증서 내 서명이 인증 기관의 것인지 검증하고(인증서의 서명은 인증 기관의 공개 키 PC로만 검증 가능) 검증 결과에 문제가 없으면 이 인증서는 확실히 인증 기관이 발행한 것
10. 인증 기관을 통해 A의 인증서임을 확인 후 인증서에서 A의 공개키 PA를 가져옴.

- 전달 과정에서 문제는 없을까?
  1. X가 A로 위장해 B에게 공개키 PX를 전달하려 함
  2. 하지만 B는 인증서로 전달되지 않은 공개키를 신뢰할 필요가 없음
  3. X가 A로 위장해 자신의 공개키를 인증 기관에 등록하려고 해도 X는 A의 메일 주소가 없기 때문에 인증서를 발행할 수 없음.
- 인증기관의 진위여부
  - 인증기관의 공개키 PC도 디지털 인증서로 전달. 이 인증기관의 인증서는 상위 인증기관이 서명.
- 최상위 인증기관(루트 인증 기관), 루트 인증 기관이 자신을 인증하는 인증서(루트 인증서)

이러한 일련의 구조를 공개키 기반 구조라고 함.
