# 자료 구조 분류

## 1. 물리적 구조: 메모리 (Hardware Level)
컴퓨터가 데이터를 메모리에 저장하는 방식은 본질적으로 단 두 가지만 존재합니다. 모든 자료구조는 이 두 가지 재료 중 하나로 지어집니다.

### 연속적 배치 (Contiguous Allocation)
- 메모리 공간을 한 덩어리로 빌려 데이터를 빈틈없이 붙여 넣습니다. 
- 이것이 배열(Array)의 본질입니다. 인덱스로 즉시 접근이 가능하지만 크기 변경이 어렵습니다.

### 불연속적 배치 (Non-contiguous Allocation)
- 메모리를 여기저기 흩뿌려 사용하되, 주소(Pointer)로 서로를 연결합니다. 
- 이것이 연결 리스트(Linked List)의 본질입니다. 데이터 추가와 삭제가 자유롭습니다.

## 2. 데이터의 형태: 관계의 모양 (Topology)
데이터들이 서로 어떤 비주얼로 연결되어 있는지를 나타냅니다.

### 선형 구조 (Linear)
- 데이터가 앞뒤 1:1로만 연결된 직선 모양입니다. 기차처럼 한 줄로 늘어선 모든 형태를 말합니다. (예: 스택, 큐)

### 비선형 구조 (Non-Linear)
- 데이터가 여러 갈래로 뻗어 나가는 모양입니다. 부모-자식 관계나 복잡한 네트워크망을 표현합니다. (예: 그래프)

## 3. ADT(Abstract Data Type): 데이터를 다루는 논리적 규칙(추상적 자료형) 
ADT는 무엇을 할 것인가에 대한 약속입니다. 
가장 넓은 범위인 컬렉션에서 시작하여 구체적인 규칙이 추가되며 뻗어 나갑니다.

- 컬렉션 (Collection): 모든 데이터 꾸러미를 통칭하는 최상위 설계도입니다.
  - 리스트 (List): 데이터를 순서대로 나열하겠다는 규칙입니다.
    - 스택 (Stack): 나중에 들어온 것을 먼저 꺼내는 특수 리스트.
    - 큐 (Queue): 먼저 들어온 것을 먼저 꺼내는 특수 리스트.
  - 그래프 (Graph): 데이터 간의 관계를 자유롭게 연결하겠다는 규칙입니다.
    - 트리 (Tree): 사이클이 없는 계층적 그래프.
      - 이진 트리 (Binary Tree): 자식이 최대 2개인 트리.
        - 이진 탐색 트리 (BST): 탐색 효율을 위해 대소 관계를 정렬한 트리.
        - 힙 (Heap): 우선순위 관리를 위해 부모-자식 관계를 정렬한 트리.

  - 특수 목적 ADT: 형태보다 기능적 규칙이 강조된 설계도입니다.
    - 맵 (Map) : 데이터의 형태보다 키(Key)와 값(Value)의 쌍이라는 관계 규칙이 핵심인 ADT입니다.
      - 핵심 규칙: 키를 넣으면 그에 대응하는 값을 즉시 돌려준다. 키는 중복될 수 없다.
      - 형태보다 기능인 이유: 내부적으로 배열(해시 테이블)을 쓰든 트리(Red-Black Tree)를 쓰든, 사용자는 오직 키로 값을 찾는다는 기능에만 집중하기 때문입니다.
    - 집합 (Set): 데이터들 사이의 순서나 계층보다 중복 금지라는 규칙이 핵심인 ADT입니다.
      - 핵심 규칙: 동일한 데이터를 두 번 담을 수 없다. 특정 데이터가 들어있는지 확인하는 것이 주 목적이다.
      - 형태보다 기능인 이유: 데이터가 어떻게 배치되어 있는지보다 유일성(Uniqueness)을 보장한다는 기능적 약속이 훨씬 중요하기 때문입니다.
    - 우선순위 큐 (Priority Queue):데이터가 들어온 순서가 아니라 중요도라는 규칙에 따라 움직이는 ADT입니다.
      - 핵심 규칙: 가장 높은 우선순위를 가진 데이터를 먼저 내보낸다.
      - 형태보다 기능인 이유: 큐는 보통 선형으로 생각하지만, 우선순위 큐는 내부적으로 비선형 트리(힙)로 돌아가는 경우가 많습니다. 사용자는 내부 모양이 무엇이든 가장 중요한 게 먼저 나온다는 규칙만 보고 사용합니다.

## 4. 입체적 정체성
- 힙(Heap)의 입체적 정체성
| 관점 | 분류 내용 | 설명 |
| :--- | :--- | :--- |
| 물리적 구조 (Physical) | 배열 (Array) | 메모리 효율과 인덱스 계산 속도를 위해 배열을 선택함 |
| 형태적 모양 (Shape) | 비선형 (트리) | 부모와 자식의 우선순위를 비교하기 위해 트리 모양을 빌려옴 |
| 추상적 규칙 (ADT) | 우선순위 큐 | 가장 중요한 데이터부터 내보내겠다는 약속을 지킴 |

- 개발자가 처한 상황에 따라 필요한 분류 기준이 다릅니다. 
  - 메모리를 아껴야 하는 상황이라면? → 물리적 구조를 먼저 봅니다. (배열 vs 리스트)
  - 데이터 간의 복잡한 관계를 정의한다면? → 선형 vs 비선형을 봅니다. (리스트 vs 그래프)
  - 데이터의 논리적 흐름을 설계한다면? → 추상적 구조를 봅니다. (스택 vs 큐)
