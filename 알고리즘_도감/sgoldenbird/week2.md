# 1.6 해시테이블 
- 키(데이터 식별자)와 값(데이터 내용)이 한 쌍 
- 데이터의 유연한 저장과 빠른 접근 가능 
```
1. 물리적 층위: 배열 
2. 논리적 층위: 해시함수 (e.g. mod 연산)
  - 추상적 데이터를 인덱스로 변환하는 논리계층 
3. 보완적 층위: 연결리스트 또는 트리 
  - 충돌이 발생했을 때 배열의 한계를 극복하기 위해 동적으로 크기가 변하는 자료구조를 덧붙인다. 
  - 체이닝 방식: 배열의 각 요소가 다시 linked list/tree의 시작점을 가리키게 만든다. 즉, 배열 안에 또다른 자료구조가 들어가있는 형태 
```
- 검색을 효율적으로 하기 위해 사용되는 자료구조
  - 선형탐색: 앞에서부터 차례대로 확인. 데이터 양에 비례해 계산시간이 늘어나므로 탐색에는 비효율적 
  - 해시테이블은 해시함수를 이용해 키에 해당하는 해시값을 계산하고, 배열 내의 특정 데이터에 빠르게 접근. 
    - mod(modulo) 연산: 해시테이블의 인덱스 배정 방식 중 가장 대표적, 기본적. 
    - mod연산은 배열의 크기를 소수(prime number)로 하는 것이 좋다. → 해시값이 고르게 분포되어 충돌이 줄어들기 때문

- 해시 함수
  - 해시함수에 따라 해시테이블 성능 천차만별. 나쁜 해시 함수는 충돌 극대화. 검색, 추가, 삭제 속도 O(1) → O(n) 으로 떨어질수 있음 
  - 일반적인 개발 → 대부분의 언어, 라이브러리가 이미 최적화해둔 해시함수 그대로 사용 (e.g. Java의 String 클래스의 hashCode() 메소드)
  - 데이터 특성이 독특하거나 극도로 빠른 성능이 필요한 보안, 임베디드 분야에서는 개발자가 직접 해시함수 설계 

- 해시값이 충돌할때는 리스트 구조를 이용하고 있으므로 저장할 데이터 수가 정해져 있지 않더라도 유연하게 대응 
  - 충돌: 데이터 저장 위치가 겹치는 것 
  - 리스트 구조에서는 선형탐색
  - 충돌 시 처리 방법에는 체이닝(연쇄법) 외에도 개방 주소법(open addressing) 등이 있다. 
    - 개방 주소법
      - 충돌이 발생하면 다음 후보가 될 주소(배열 상의 위치)를 구해서 거기에 저장하는 방식.  
      - 해당 주소에도 데이터가 존재하면 비어있는 곳을 찾을 때까지 다음 후보 주소를 구한다. 
      - 다음 주소를 어떻게 구하는가는 해시 함수를 여러개 사용하는 방법이나 '선형탐사' 등 몇가지 방법이 있다.  

- 해시테이블은 프로그래밍 언어의 연관 배열(associative array)등에 사용
  - 일반 배열: 숫자 인덱스. arr[0] = "Apple"
  - 연관 배열: 키-값 쌍. 연관된 키로 value를 찾는다. map["fruit"] = "Apple"

# 1.7 힙 
- 그래프의 트리 구조 
  - 이진 트리에 속하므로 각 노드는 최대 2개의 자식 노드를 가질 수 있다.
- 일반적으로 배열을 이용해 구현 ( → 노드는 포인터를 별도로 저장하지 않고 value만 가진다.)
- 우선순위 큐(priority queue: 데이터 추가는 자유롭게, 삭제는 작은 값부터) 구현에 자주 사용
- 데이터 중 최소값을 자주 추출해야 하는 경우, 힙이 편리 


## 힙의 조건
- 노드는 `위`에서부터 채워지며 같은 층에서는 `왼쪽`부터 채워진다. 
- `자식 노드의 숫자 > 부모의 숫자` 따라서 루트에 가장 작은 수가 들어있다. 
- 데이터 추가 O(log n)
  - 가장 아래층에 있는 왼쪽 노드부터 값을 채운다.  
  - 부모의 숫자가 더 클때는 부모와 자식을 교환. 이 처리를 교환이 발생하지 않을때까지 반복
  - 가장 후미에 데이터를 추가한 후 힙 조건을 만족할 때까지 부모 숫자와 비교하며 위쪽으로 진행 → 계산 시간은 트리의 높이에 비례 
- 데이터 삭제 O(1)
  - 가장 위에 있는 숫자가 추출 → 가장 후미에 있는 숫자를 가장 위로 이동 (p36)
  - if 자식 < 부모 → 부모와 자식 교환. 좌우 자식 중 더 작은 쪽과 교환. 이 처리를 교환이 발생하지 않을때까지 반복
  - 항상 가장 위에 최솟값이 있으므로 데이터 수에 상관없이 O(1)시간
- 데이터 삭제 후 재구축 O(log n)
  - 가장 후미에 있는 데이터를 가장 위로 가져온 후 자식과 비교해가며 아래 방향으로 진행 → 계산 시간은 트리의 높이에 비례 

# 1.8 이진 탐색 트리(Binary Search Tree)
- 그래프의 트리 구조 
- 이진 탐색의 개념을 트리 구조로 표현한 것
- 데이터 검색, 추가 할때 위치는 현재 위치의 데이터와 대소를 비교하기만 하면 왼쪽으로 진행하면 좋을지 오른쪽으로 진행하면 좋을지 알 수 있다.  
- 데이터 검색, 추가, 삭제 모두 O(log n) 
  - 트리의 높이(단계, 깊이)에 비례하는 시간. 노드가 n개이고 트리가 균형 잡힌 경우.
  - 최악의 경우 트리가 한쪽으로 치우쳐져서 선형 구조가 될 수 있는데, 이때는 트리가 높아져서 O(n)까지 떨어질 수 있다.
- 이진 탐색 트리를 확장한 데이터 구조 
  - 자가 균형 이진 탐색 트리(self-balancing binary search tree): 트리의 균형을 유지하기 위한 추가적인 규칙과 연산이 있는 이진 탐색 트리. (예: AVL 트리, 레드-블랙 트리)
  - B-트리(Balanced Tree): 디스크 기반 데이터베이스 시스템에서 자주 사용되는 트리 구조로, 노드 자식수에 제한을 두지 않고 트리의 균형을 도모. 대용량 데이터 저장에 적합.


## BST의 조건
1. 모든 노드는 자신을 기준으로 왼쪽 가지에 포함되는 어떤 숫자보다도 큰 숫자가 된다.(p38)  
⇒ 이진 탐색 트리의 최소 노드는 루트 노드 기준 왼쪽 가지의 가장 끝에 있는 노드
2. 모든 노드는 자신을 기준으로 오른쪽 가지에 포함되는 어떤 숫자보다도 작은 숫자가 된다. 
⇒ 이진 탐색 트리의 최대 노드는 루트 노드 기준 오른쪽 가지의 가장 끝에 있는 노드

- 데이터 접근(검색) O(log n)
  - 최상단 노드부터 탐색 시작 
  - 찾는 숫자를 현재 노드 값과 비교해서 작으면 왼쪽으로 크면 오른쪽으로 진행 
- 데이터 추가 O(log n)
  - 추가하려는 값을 루트 노드부터 비교해서 작으면 왼쪽, 크면 오른쪽으로 진행
- 데이터 삭제 O(log n)
  - 삭제하려는 노드가 자식이 없는 경우: 그냥 삭제
  - 삭제하려는 노드가 자식이 하나인 경우: 
      1. 대상 노드를 삭제 
      2. 삭제한 노드의 위치로 자식 노드를 이동
  - 삭제하려는 노드가 자식이 둘인 경우
      1. 대상 노드를 삭제
      2. 삭제한 노드의 왼쪽 가지에서 최대 노드를 찾는다 또는 오른쪽 가지에서 가장 작은 노드를 찾는다.
      3. 삭제한 노드의 위치로 자식 노드를 이동
      4. 이동 대상 노드도 자식노드를 지닌다면 같은 처리를 재귀적으로 반복한다.  
          - 예를 들어 책의 그림처럼 노드 4를 삭제된 위치로 옮긴다고 가정해 보겠습니다.
          - 4가 삭제된 노드의 위치로 이동합니다.
          - 4가 떠난 원래 자리는 이제 비어 있게 됩니다.
          - 이때 4의 자식이었던 3이 4의 원래 자리로 올라옵니다.
          - 만약 3에게도 자식인 1이 있다면, 3이 올라간 빈자리를 다시 1이 채우게 됩니다.
