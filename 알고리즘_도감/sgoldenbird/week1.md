# 0.1 알고리즘이란?

## 50개를 정렬하는 데 우주의 역사보다 긴 시간이 필요하다면?

- 완전 탐색에 의한 정렬(brute force): 모든 가능한 조합을 다 만들어놓고 그 중 정답을 찾는 것 
  $n! = n \cdot (n-1) \cdot (n-2) \cdots 3 \cdot 2 \cdot 1$
- 선택 정렬: 무작위로 조합을 만드는게 아니라 확실하게 하나씩 자리를 채워가는 것 
  $\displaystyle
  \frac{n(n+1)}{2} = \frac{n^2 + n}{2}=\frac{1}{2}n^2 + \frac{1}{2}n = O(n^2)
  $
  전체 값에서 n^2가 차지하는 비중이 압도적으로 크기 때문에 알고리즘 효율성을 따질때는 자잘한 숫자들은(1/2, n) 무시하고 
  최고차항인 n^2만 남겨서 비교. 이를 Big-O표기법으로 O(n^2)으로 표현. 즉, 선택 정렬은 n^2급 알고리즘 
  (데이터가 10배 증가 → 연산량은 약 10^2배 증가) 

# 0.2 계산 시간을 측정하는 방법

## 입력 크기(n)와 계산 시간과의 관계 이해하기 
- O(n) → 입력에 비례해서 증가
- O(n²) → 더 빠르게 증가
- O(log n) → 천천히 증가
- O(1) → 입력이 커져도 시간 거의 그대로

## 계산 시간 구하는 법 
- 계산 시간에는 '스탭 수'를 활용. 
- 계산을 종료하기까지 "기본 단위(1스탭)를 몇 회 실행했는가"로 계싼 시간 측정

## 계산 시간을 표현하는 방법 

### Big-O 표기법
입력의 크기 n의 변화에 따라 계산 시간이 어느 정도 달라지는지 파악 할 수 있다. 
1. "무한대"가 기준
- 빅오는 데이터($n$)가 10개, 100개일 때가 아니라 무한히 많아질 때를 가정합니다.
$n \log n+2n$ 에서 초반에는 $2n$이 더 클 수 있어도, $n$이 커지면 결국 $n \log n$이 $2n$을 추월합니다.
그래서 "마지막에 누가 가장 큰가"가 기준입니다.
2. "대장"만 남기기 (Dominant Term)
- 식에서 가장 영향력이 큰 항(가장 빨리 증가하는 항)만 남기고 나머지는 버립니다.
$3n \log n + 2n$ → $2n$은 상대적으로 너무 작아서 무시 
3. "계수, 상수"는 무시
- 증가하는 '추세'가 중요하지, 앞에 붙은 숫자는 중요하지 않습니다.$3n \log n$ → 숫자 3을 제거 → $O(n \log n)$
- 빅오 표기법에서 숫자 1은 단순히 '한 번'을 뜻하는 게 아니라, '데이터 양($n$)이 아무리 많아져도 연산 횟수가 변하지 않는 상수 범위'를 통틀어서 표현하는 기호입니다. ($n$이 상수라면 $O(1)$이지만, $n$이 입력값의 규모에 따라 변하는 변수라면 $O(n)$으로 표기)
  - 단방향 연결 리스트: 다음 노드 주소 1개 변경 → $O(1)$
  - 양방향 연결 리스트: 이전/다음 노드 주소 2개 변경 → $O(2)$ → $O(1)$

# 1.2 리스트(링크드 리스트) 
- 리스트: 넓은 의미의 리스트는 데이터를 순서대로 나열하는 모든 것(배열, 링크드 리스트도 리스트의 한 종류)

## 링크드 리스트 
- 각 데이터는 포인터가 있으며 다음 데이터의 메모리 위치를 가리킨다. 마지막 데이터는 포인터를 가지고 있지 않다. 
- 순차 접근(sequential access): 데이터는 메모리 상의 연속된 위치에 저장되지 않아도 되며 일반적으로 떨어진 영역에 흩어져서 저장된다. 때문에 포인터를 처음부터 순서대로 따라가야만 원하는 데이터에 접근할 수 있다. 
- 데이터 검색(접근) = 선형 탐색 O(n)
  - 리스트 앞에서부터 차례로 진행 
- 데이터 추가 = O(1) 
  - 추가할 위치의 앞뒤, 2개의 포인터를 변경만 하면 되므로 n에 관계없는 상수 시간이 된다. 
- 데이터 삭제 = O(1)
  - 포인터의 방향을 바꾸면 된다. 직접 삭제하는게 아니므로 메모리에는 남지만 어디에서도 접근할 수 없으므로 일부로 삭제할 필요가 없다. 이후에 이 영역이 사용될 때 덮어쓰기가 되어 다시 사용할 수 있게 된다. 

## 다른 리스트 
- 원형 리스트(순환 리스트)
  - 마지막 데이터의 포인터가 선두를 가리키는 것. 선두나 후미 개념이 없다. 
- 양방향 리스트 
  - 포인터 두개를 사용해서 앞뒤 데이터를 가리키는 것
  - 리스트를 뒤에서 앞으로도 추적할 수 있어 편리하다. 
  - 단, <mark>**포인터 수가 늘어나므로 데이터 저장을 위한 영역이 많아지는 결점**</mark>이 있다.
  - 또한 데이터 추가나 삭제 시에도 변경해야 할 포인터가 늘어난다.    

## 작동 원리
- 노드: 연결 리스트를 구성하는 하나의 단위
  - 데이터 필드(value) 
  - 링크 필드(pointer): 다음 노드가 어디있는지 가리키는 주소값

- pointer
  - 단순한 화살표가 아니라 메모리 주소를 저장하는 8바이트짜리 숫자 저장 공간. 주소값을 담고 있는 변수
  - 32비트(4바이트) 컴퓨터: 포인터 하나당 4바이트 저장공간 차지. 주소 하나 적는데 4바이트 필요
  - 64비트(8바이트) 컴퓨터: 포인터 하나당 8바이트 저장공간 차지

- 단방향 노드: 데이터 크기+포인터(8바이트)
- 양방향 노드: 포인터(8바이트)+데이터크기+포인터(8바이트)

- 만약, 우리가 저장하려는 데이터가 아주 작은 숫자라면 양방향 리스트의 경우 배보다 배꼽이 커질 수 있다. 예를 들어 실제 데이터가 1바이트, 포인터 공간이 16바이트라면 1바이트 저장하려고 17바이트를 쓰게됨. 


# 1.3 배열 
- 연속된 메모리 영역에 순서대로 저장 
- 임의 접근(random access): 데이터가 연속된 위치에 저장되므로 원하는 데이터의 위치를 계산해서 바로 접근할 수 있다.
- 배열 변수는 배열의 첫번째 요소가 시작되는 메모리 주소(base address)를 담고 있다. 컴퓨터는 이 시작점만 기억. 
- 참고) 배열 변수 콘솔 결과 
  - 저수준 언어(C, 등): 진짜 메모리 주소 
  - 자바: 주소와 유사한 해시코드가 포함된 문자열 
  - JS, Python: 배열 안의 내용물 
- 데이터 검색(접근) = O(1)
- 데이터 추가 = O(n) 
  - 배열의 선두에 데이터를 추가하려고 하면 기존 데이터들을 한 칸씩 뒤로 밀어야 한다.
  - 배열의 맨 끝에 데이터를 추가하는 것은 O(1). 밀어낼 필요가 없기 때문.
- 데이터 삭제 = O(n)
