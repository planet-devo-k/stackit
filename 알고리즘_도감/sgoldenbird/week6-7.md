# 5.1 보안과 알고리즘

## 무결성 Integrity

- 데이터가 전송되거나 저장될 때, 중간에 누군가에 의해 위조, 변조, 삭제되지 않고 원래 그대로의 온전함을 유지하는 성질

## 인터넷에서 데이터 주고 받을 때 발생할 수 있는 대표적인 문제 4가지

- 이 문제들은 사람 사이에서만 발생하는 것이 아니라 웹사이트를 열람하는 경우에도 동일하게 발생할 수 있습니다.
- 전자 서명 기술에서 문제가 되는 공개키의 소유자를 식별할 수 없는 문제를 해결하기 위해 전자 인증서라는 기술도 사용합니다.

### 1. 도청 interception → 암호화 encryption

- 제3자가 중간에서 몰래 훔쳐보는 행위

### 2. 위장 spoofing → 메시지 인증 코드 || 전자 서명, 전자 인증서

- 제3자가 다른 사람인 척 가장하는 행위
- 피싱 사이트

### 3. 변조 falsification → 메시지 인증 코드 || 전자 서명, 전자 인증서

- 제3자가 메시지를 몰래 바꾸는 행위
- 통신 상의 장애로 데이터가 망가진 상태로 전달되는 경우도 포함

### 4. 사후 부인 repudiation → 전자 서명, 전자 인증서

- 메시지를 보낸 사람이 나중에 자신이 보낸 메시지가 아니라고 주장하는 행위

# 5.2 암호의 기본

- 암호문 ciphertext: 암호화한 데이터
- 복호화 decryption: 암호문을 원래의 데이터로 되돌리는 과정

## 암호화

데이터에 어떤 연산을 적용해서 컴퓨터가 해석할 수 없는 숫자로 변경하는 것

- 데이터에는 텍스트, 음악, 사진 등 다양한 형식이 있지만 컴퓨터 내에서는 모든 데이터가 2진수로 관리
- 이러한 데이터는 컴퓨터에게 있어 의미를 지닌 숫자들의 나열
- 암호문도 숫자의 나열이긴 하나, 컴퓨터가 해석할 수 없는 임의의 숫자로 구성

## 수치계산

- 글자나 키를 (즉, 모든 데이터) 0과 1이라는 숫자로 바꾼 뒤, 컴퓨터가 비트 단위로 대조하고 연산(XOR 등)하여 값을 뒤섞거나 다시 되돌리는 과정
- 암호화의 수치 계산에서는 키를 이용하지만, 키도 숫자로 만들어집니다.
  - XOR 연산(배타적 논리합): 두 숫자가 같으면 0, 다르면 1이 되는 연산. 암호화 복호화에 가장 흔하게 쓰이는 대표적인 수치 계산

# 5.3 해시함수

- 해시함수: 주어진 데이터를 고정 길이의 불규칙한 숫자로 변환하는 함수
- 해시값: 변환된 불규칙한 숫자. 해시값은 16진수(0~9, a~f)로 표기하는 경우가 많다. 해시값도 데이터의 일종이므로 표기는 16진수로 하지만 내부에서는 2진수로 관리된다.
- 참고) 해시테이블
  - 해시테이블은 데이터를 배열 형태로 저장
  - 해시 함수는 입력된 키 값을 받아 배열의 인덱스로 변환
  - 해시테이블의 키 데이터(문자열, 파일, 아주 큰 숫자 등) 크기와 형태가 제각각 → 해시 함수는 무한한 종류의 키들을 해시테이블이 준비한 한정된 크기인 배열 인덱스로 압축, 변환하는 역할

## 해시함수의 특징

1. 데이터 크기에의해 해시값 길이가 바뀌지 않는다. 어떤 크기의 데이터를 넣든 항상 고정된 길이의 해시값이 나온다.
2. 같은 입력에 대해서는 항상 같은 출력을 제공한다.
3. 입력의 작은 변화에도 출력이 크게 달라진다.
4. 전혀 다른 데이터를 입력해도 드물지만 같은 해시값이 나올 수 있다. (해시값 충돌 collision)
5. 해시값으로부터 원 데이터를 역산하는 것이 사실상 불가능하다. 데이터 입력과 출력의 흐름이 단방향. 이것이 암호화와 크게 다른점
6. 해시값을 결정하는 계산이 비교적 간단하다.

## 암호화 vs 해시함수

### 암호화 (Encryption) -> 양방향

- 암호화는 데이터를 안전하게 전송하고, 나중에 원래대로 되돌려 읽기 위해 사용합니다.
- 방향성: 양방향
- 작동 방식: 평문(원본)을 알아볼 수 없는 암호문으로 바꾸는 과정(암호화)이 있으면, 비밀키를 가진 사람이 이를 다시 원래대로 되돌리는 과정(복호화)이 반드시 존재합니다.

### 해시 함수 (Hash Function) -> 단방향

- 해시 함수는 데이터의 고유한 특징을 추출해 내는 일종의 디지털 지문 역할을 합니다.
- 방향성: 단방향
- 작동 방식: 이미지의 다섯 번째 특징에 밑줄이 쳐진 것처럼, 결과물(해시값)을 가지고 원래 무엇을 입력했는지 역산하는 것이 수학적으로 불가능합니다.
- 사용 목적: 비밀번호를 저장할 때. 식별자.
  - 우리가 웹사이트에 회원가입을 하고 비밀번호를 설정할 때, 서버는 우리가 입력한 비밀번호(예: myPassword123)를 그대로 저장하지 않습니다.
  - 만약 그대로 저장했다가 서버가 해킹당하면 모든 사용자의 비밀번호가 그대로 유출되기 때문입니다.
  - 그래서 서버는 비밀번호를 해시 함수에 넣어서 나온 결과물(해시값)만 데이터베이스에 저장합니다.
  - 사용자가 로그인할 때: 입력한 비밀번호를 다시 해시 함수로 돌려서, 데이터베이스에 저장된 해시값과 일치하는지만 확인합니다.
  - 해커가 서버를 해킹했을 때: 해시값만 손에 쥐게 됩니다. 앞서 설명해 드린 것처럼 해시 함수는 단방향이라 역산이 불가능하므로, 해커는 해시값을 보고도 원래 비밀번호가 무엇인지 알아낼 수 없습니다.

### 해시 함수의 알고리즘

- SHA-2 등
- 알고리즘에 따라 계산 방법이 다르지만 예를 들어 SHA-1은 데이터에 덧셈이나 시프트 연산 등을 수백회 반복해서 해시값 생성.
- 알고리즘이 달라지면 같은 데이터를 입력해도 해시값이 다르다.

# 5.4 데이터를 암호화 하는 방식1: 공통키 암호 방식

암호화와 복호화에 같은 키를 사용

- 대칭형 암호 방식, 비밀키 암호 방식, 공유키 암호 방식 등으로도 불린다.
- 시저암호(Caesar cipher), AES(Advanced Encryption Standard), DES(Data Encryption Standard), OTP 등이 대표적인 공통키 암호 방식

문제

- 키 분배 문제: 키를 안전하게 공유하는 방법이 필요하다. 키가 제3자에게 노출되면 보안이 완전히 무너진다.
- 공통키 암호 방식은 사람이 늘어나면 필요한 키의 수가 급격하게 증가한다. $n$이 사람 수일 때, 필요한 총 키의 개수는 $n(n-1)/2$개

해결방법

- 키 교환 프로토콜 사용 (디피-헬먼 알고리즘)
  - 두 사람이 인터넷 같은 공개된 공간에서 암호화에 사용할 '공통키'를 안전하게 나누어 가지기 위한 통신 규칙
  - https:// 는 TLS(과거에는 SSL이라고 불렸던 기술)라는 보안 프로토콜을 사용하고 있다는 뜻
  - 이 TLS 안에는 안전한 통신을 하기 위해 여러 단계의 기술이 들어가는데, 그중 첫 번째 단계가 바로 서로 비밀키를 안전하게 나누어 갖는 단계(키 교환)입니다. 이때 전 세계 웹사이트들이 가장 많이 선택해서 사용하는 수학 공식이 바로 디피-헬먼 알고리즘입니다.
- 공개키 암호 방식

# 5.5 데이터를 암호화 하는 방식2: 공개키 암호 방식

암호화와 복호화에 다른 키를 사용

- 비대칭 암호 등으로 불린다.
- 암호화에 사용하는 키: 공개키 (public key)
- 복호화에 사용하는 키: 비밀키 (secret key)
- 공개키 암호의 구체적인 알고리즘으로는 RSA암호, 타원곡선 암호 등
- 불특정 다수 간 데이터 교환이 쉽다.

공개키로는 암호문을 복호화 할 수 없으므로 제3자 X는 원 데이터를 얻을 수 없다.

- 데이터를 전달받는 사람 B가 공개키와 비밀키를 만든다.
- 그 중 공개키를 A에게 전송
- A는 받은 공개키를 사용해 데이터를 암호화
- A는 암호문을 B에게 전송. B는 받은 암호문을 비밀키를 사용해 복호화

문제

- 공개키의 신뢰도에 관한 문제: 공개키 자체에는 누가 작성한지 표시하는 수단이 없다.
- man in the middle 공격: 도중에 공개키를 바꿔치기해서 데이터를 가로채는 기법
  - X가 공개키를 자신이 만든 키로 바꾸고 A에게 전달할 수 있다.
  - A는 가짜 공개키로 데이터를 암호화하고 X가 이를 가로챈다.
  - X가 B의 공개키인 원 공개키로 가짜 데이터를 암호화 한 후 B에게 전달
- 암호화, 복호화에 시간이 오래 걸린다. 따라서 상세한 데이터를 연속적으로 교환하는 구조에는 적합하지 않다.

해결방법

- 전자 인증서: 공개키의 신뢰도에 관한 문제는 공개키 작성자를 명확히
- 하이브리드 암호 방식: 암호화, 복호화에 시간이 오래 걸리는 문제 해결

RSA 암호 등 구체적인 공개키 암호 방식을 구현하는 알고리즘이 고안된 것은 인터넷 보안에서 큰 의미

- 공개키 암호 방식을 구현하는 알고리즘을 찾는건 아래 사항들을 모두 만족해야 하므로 쉽지 않다.

1. 특정 숫자를 사용해 암호화
2. 다른 숫자를 사용해 원 데이터로 복원화
3. 한쪽 키에서 다른쪽 키를 추측할 수 없는 연산
