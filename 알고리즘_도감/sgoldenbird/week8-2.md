# 7.1 유클리드 알고리즘

## 두 수의 최대공약수(GCD)

- 일반적으로 두 수를 소인수분해해서 공통되는 소수를 구한다. 하지만 이 방법은 두 수가 커질수록 소인수분해가 어렵다.
- 유클리드 알고리즘에서는 나눗셈만 반복하면 최대공약수를 구할 수 있다.

## 원리

나눈수와 나머지로 다음 mod 연산 반복. 나머지가 0이 됐을때 마지막 계산에서 나누눈 수가 최대공약수

1. 큰수1 mod 작은수1 = 나머지1
2. 작은수1 mod 나머지1 = 나머지2
3. 나머지1 mod 나머지2 = 나머지3
4. 나머지가 0이 될때까지 반복

# 7.2 소수 판별법

- 소수: 1과 자신 이외는 약수로 가지지 않는 1보다 큰 자연수. RSA 암호에서는 매우 큰 소수를 다루므로 소수 판별법이 중요하다.

## 페르마 테스트(= 확률적 소수 판별법)

- 어떤 수가 소우일 가능성이 높은지 판별하는 것
- 페르마의 소정리를 만족하는지로 소수를 판별하는 방법. 아마도 소수
- RSA 암호에서 사용되는 소수판별법에는 페르마테스트를 개선한 밀러-라빈 테스트가 사용되고 있다. 이 방법에서는 테스트를 반복해서 소수가 아닌 확률이 0.5의 80승보다 작은 단계에서 해당 수를 소수라고 판별한다.

### 소수의 성질: 페르마의 소정리

- if(n < 소수) n^소수 mod 소수 = n
- 그러나 모든 n이 위 식을 만족한다고 해서 소수라고 할 수는 없다. 모든 n이 식을 만족하는 합성수가 존재하기 때문이다. 이런 합성수를 카마이클 수 또는 절대 유사소수라고 한다. (p185 참고)

## AKS 소수 판별법

- 입력 길이가 다항식 오더인 알고리즘으로 소수 판별이 가능한지는 오랫동안 풀지 못한 난제였으나 가능하다는 것이 증명
- 다항식 오더라고 하지만 차수가 높기 때문에 페르마 테스트처럼 계산 속도가 빠른 방법이 주로 사용되고 있다.
- 다항식 오더(Polynomial Order)
  - 컴퓨터 과학에서 알고리즘의 실행 속도나 복잡도를 나타낼 때 쓰는 다항 시간(Polynomial Time)
  - 숫자가 커질 때 계산 시간이 늘어나는 방식<br/>
    컴퓨터가 어떤 문제를 풀 때, 입력값이 커지면 계산해야 하는 양도 당연히 늘어납니다. 이때 늘어나는 속도가 어떤 '수학적 형태'를 띠는지가 중요한데, 크게 다항 시간과 지수 시간으로 나뉩니다.
    - 지수 시간 (Exponential Time): 계산 시간이 $2^n$, $3^n$처럼 변수($n$)가 지수에 가 있는 형태로 늘어나는 것을 말합니다. (Big-O 표기법으로는 $O(2^n)$라고 씁니다.)
    - 다항 시간: 데이터의 크기($n$)가 커질 때, 계산 시간이 $n^2$, $n^3$, $n^4$처럼 변수($n$)의 거듭제곱 형태로 늘어나는 것을 말합니다. (Big-O 표기법으로는 $O(n^k)$라고 씁니다.)
  - 왜 이게 난제였고 중요할까?<br/>
    수학자들과 컴퓨터 과학자들은 어떤 알고리즘이 현실적으로 '컴퓨터로 풀 수 있는 문제'인지를 판가름할 때 이 다항 시간을 기준으로 삼습니다.
    - 지수 시간 알고리즘: 숫자가 조금만 커져도 계산량이 폭발적으로(우주적인 숫자로) 늘어나서 최신 슈퍼컴퓨터로도 몇 백 년이 걸려 사실상 풀지 못합니다.
    - 다항 시간 알고리즘: 숫자가 커져도 계산량이 비교적 완만하게 늘어나서 컴퓨터가 현실적인 시간 내에 답을 낼 수 있습니다.
      AKS 알고리즘이 나오기 전까지는 "어떤 아주 큰 숫자가 소수인지 아닌지 완벽하게 판별해내는 알고리즘을 다항 시간(현실적인 시간) 내에 작동하게 만들 수 있는가?"가 수학계의 엄청난 난제였습니다.
      AKS 소수 판별법은 "그것이 가능하다!"라는 것을 수학적으로 증명해 낸 최초의 알고리즘입니다. (정확히는 $O((\log n)^6)$ 정도의 다항 시간이 걸립니다.
  - 그런데 왜 페르마 테스트를 쓸까?<br/>
    다항 시간 알고리즘이긴 하지만, AKS 알고리즘은 실제 계산해보면 차수(거듭제곱 수)가 너무 높아서 숫자가 커질 때 생각보다 계산 속도가 느립니다. 이론적으로는 현실적인 시간 안에 끝난다는 게 증명되었지만, 실제 컴퓨터로 돌리기에는 여전히 무거운 편입니다. 반면에 페르마 테스트 같은 방법은 확률적인 방법(가끔 합성수를 소수라고 잘못 판정할 확율이 있음)이긴 하지만, 계산 속도가 압도적으로 빠르기 때문에 실무나 보안 시스템(RSA 암호화 등)에서는 페르마 테스트나 이를 보완한 밀러-라빈 테스트를 주로 사용합니다.

# 7.3 페이지랭크

- 검색사이트에서 검색 결과 순위를 결정하기 위해 사용되는 알고리즘
- 페이지 간의 링크 구조로부터 페이지의 가치를 산출하는 알고리즘
- 페이지 랭크에서는 링크된 수가 많을 수록 중요한 페이지라고 판단. 각 페이지의 중요도가 계산에 의해 수치화됩니다.
  - 링크돼 있는 페이지 점수는 링크를 하고있는 페이지 점수의 합
  - 단, 링크가 여러 페이지로 나누어지는 경우, 링크 점수를 균등하게 배분합니다.
    <br/> 만약 나누지 않고 100점을 링크된 모든 페이지에 전부 준다면, 어떤 페이지가 아무 문서에나 링크를 수천 개씩 마구잡이로 걸어서 특정 페이지들의 점수를 비정상적으로 높이는 '꼼수(어뷰징)'가 가능해집니다. 페이지랭크는 이를 막기 위해 "링크를 많이 걸수록 각 링크의 가치는 떨어진다"는 현실적인 법칙을 체택한 것입니다. 유명한 추천인(점수가 높은 페이지)이 나 한 명만 추천해 주면 내 가치가 엄청나게 뛰지만, 그 사람이 수백 명을 동시에 추천했다면 나에게 오는 추천의 가치도 그만큼 줄어드는 것과 같은 원리입니다.
- 링크가 원형을 이루는 경우 무한 루프가 돼서 루프 내 페이지 점수가 계속 증가
- 현재 구글 검색 결과 순위는 페이지랭크만으로 결정되는 것은 아니다. 하지만 링크 구조로부터 페이지의 가치를 산출한다는 발상과 링크가 루프상태인 경우에도 계산할 수 있다는 점에서 페이지랭크라는 알고리즘은 획기적

## 랜덤 서퍼 모델

- 루프 문제는 랜덤 서퍼 모델이라는 계산 방법으로 해결
- 랜덤 서퍼는 링크를 따라 몇개의 페이지를 방문하다 재미없어지면 서핑 중단. 그리고 다른 페이지를 통해 서핑 시작. 여기서도 링크 따라 다른 페이지로 이동하다 중단. 이렇게 어떤 페이지에서 열람을 시작해서 몇 페이지 이동한 후 종료하는 동작 반복
- 이것은 페이지들을 정해진 횟수 없이 이동한 후에 전혀 다른 페이지로 순간 이동하기를 반복하는 것과 같다.
  - 확률 $\alpha$로 다른 페이지로 순간 이동
  - 확률 1-$\alpha$로 지금 있는 페이지 링크 중 하나 선택
- 특정 시점에 해당 페이지를 열람할 확률을 페이지 점수로 사용하는 것
  - 1. $1-\alpha$ (링크 이동)가 없다면: 점수의 차이가 생기지 않습니다 <br/>
       만약 알파가 1이라면, 즉 모든 서퍼가 링크를 전혀 타지 않고 무조건 순간 이동만 한다면 어떻게 될까요?
       서퍼들은 인터넷의 모든 페이지를 완전히 무작위로 날아다니게 됩니다. 링크가 100개 걸린 페이지나, 링크가 아예 없는 외딴섬 페이지나 서퍼들이 떨어질 확률이 똑같아집니다.
       결국 시간이 흐른 뒤 조사를 해보면 모든 페이지에 서퍼들이 똑같은 비율로 서 있게 됩니다. 즉, 링크를 타고 퍼지는 진짜 '인기 페이지(점수가 높은 곳)'를 골라낼 수 없게 됩니다. 따라서 $1-\alpha$(링크를 타는 확률)가 있어야만, 링크가 많이 걸린 좋은 페이지로 서퍼들이 점점 뭉치고 쌓이면서 페이지 간의 점수 차이가 생겨나기 시작합니다.
  - 2. $\alpha$ (순간 이동)가 없다면: 특정 페이지가 점수를 독점합니다 <br/>
       반대로 알파가 0이라면, 즉 모든 서퍼가 100% 링크만 타고 다닌다면 심각한 왜곡이 발생합니다. 앞서 말한 '무한 루프(함정)' 기억하시나요? 어떤 영악한 웹사이트 주인이 자기들끼리만 뱅글뱅글 도는 링크 덫을 만들어 놓으면, 링크만 타고 다니던 서퍼들은 전부 이 덫에 빠져서 영원히 나오지 못합니다.시간이 지나서 전수조사를 해보면, 전 세계 모든 서퍼가 그 루프 안에 갇혀 있게 됩니다. 시스템의 모든 점수를 그 루프가 독점해버리고, 진짜 좋은 페이지들의 점수는 0%가 되는 대참사가 일어납니다.
  - 3. 결론: 두 확률의 상호작용이 만드는 최종 점수<br/>
       결국 페이지랭크에서 '그 페이지에 서퍼가 존재할 확률(점수)'이 정상적으로 작동하려면 이 두 가지가 반드시 동시에 작용해야 합니다. 서퍼들은 $1-\alpha$(예: 85%)의 확률로 유익한 링크를 따라다니며 진짜 인기 있는 페이지에 데이터(점수)를 차곡차곡 배달합니다. 덕분에 좋은 페이지의 점수가 높아집니다.그러다가 무한 루프에 갇히거나 막다른 길에 도달하더라도, $\alpha$(예: 15%)라는 확률의 탈출구가 있기 때문에 서퍼들이 다시 빠져나와 전체 인터넷 세상으로 골고루 흩어집니다. 외딴섬 페이지도 최소한 이 15%의 확률 덕분에 가끔은 방문을 받을 기회를 얻습니다.즉, 알파와 $1-\alpha$라는 규칙이 존재하기 때문에, 서퍼들이 덫에 갇히지 않으면서도 "링크의 연결 구조에 따라 가장 자연스럽고 공평하게 서퍼들이 몰려 있는 상태(안정적인 확률 분포)"가 만들어지는 것입니다.
- 방문하고 있는 확률로 링크의 가중치를 변경해서 계산하는 것이 페이지랭크 방식

# 7.4 하노이의 탑

1. 한번에 한개의 원반만 이동 가능
2. 작은 원반 위에 그것보다 큰 원반을 둘 수 없다.

## 재귀적 알고리즘

- n개 원반 이동은 n-1개 원반 이동을 해결하는 방식을 사용. n-1개 하노이 탑 풀려면 n-2개 하노이탑 해결하는 방식 사용. 이렇게 걔속하다보면 최종적으로 한개의 원반을 푸는 방법에까지 이른다.
- T(n): n개 원반의 하노이 탑 해결하는 경우의 계산량
  - 1개: T(1) = 1
  - n개: 2T(n-1)+1
    - T(n-1): 위의 n-1개를 A → B
    - 1: 가장 큰 원반을 C로 이동
    - T(n-1): B에 있는 n-1개를 C로 이동
- 이것을 정리하면 T(n) = 2^n-1
  - 원반 1개일 때 ($n=1$)$T(1) = 1$
  - 원반 2개일 때 ($n=2$)공식 $2T(1) + 1$에 방금 구한 $T(1)=1$을 넣습니다.$2 \times 1 + 1 = 3$
  - 원반 3개일 때 ($n=3$)공식 $2T(2) + 1$에 방금 구한 $T(2)=3$을 넣습니다.$2 \times 3 + 1 = 7$
  - 원반 4개일 때 ($n=4$)공식 $2T(3) + 1$에 방금 구한 $T(3)=7$을 넣습니다.$2 \times 7 + 1 = 15$
