# 그래프 최단 경로 탐색

- 제거 === 그래프 상에서 위치에 도달, 위치로 이동

## 다이나믹 프로그래밍

- 복잡한 문제를 더 작은 하위 문제로 나누어 해결하는 알고리즘 설계 기법
- 이름만 들으면 매 순간 역동적으로 변하는 화려한 기술 같지만, 실제로는 한번 계산한 결과를 메모리에 저장해 두었다가 똑같은 계산이 필요할 때 꺼내 쓴다.
- 중복 계산을 막아 프로그램의 실행 속도를 비약적으로 조절하는 것이 핵심.

## 벨먼-포드 알고리즘 $$O(VE)$$

- 다이나믹 프로그래밍 기법을 사용하여 최단 경로를 찾는 알고리즘
- 간선의 가중치가 음수인 경우에도 최단 경로를 찾을 수 있음
- 음수 사이클(폐로)이 존재하는 경우에는 그 폐로를 계속 순회하면서 최단 경로가 무한히 작아질 수 있다. 즉, 애당초 최단 경로가 존재하지 않는다.
  - 정점의 가중치 변경 작업을 n라운드 진행해도 정점의 가중치가 계속 변경된다면 최단 경로가 존재하지 않는다는 판단을 할 수 있다.
- 정점수 v와 간선수 e가 주어졌을 때, 시간복잡도는 O(VE)로, 큰 그래프에서는 비효율적임
  - 모든 간선을 최대 V-1번 반복하여 완화(relaxation: 최단 경로가 개선되는지 확인하는 과정) 작업을 수행
  - 가중치 변경 작업(완화)을 v-1회 순회, 매 라운드마다 각 간선을 1회씩 조사하므로 계산 시간 O(e) ⇒ O(v\*e)

</br>

- 간선의 순서는 임의
- 시작정점의 가중치 + 간선의 가중치
- 같은 작업을 가중치가 변경되지 않을 때까지 반복

## 다익스트라 알고리즘 $$O((V+E)\log V)$$

- 가중치 계산과 변경을 모든 간선에 대해 반복하는 벨먼-포드 알고리즘과 달리, 다익스트라 알고리즘은 정점 선택 방법을 고민
- 우선순위 큐를 사용하여 최단 경로를 찾는 알고리즘
- 간선의 가중치가 음수인 경우에는 사용할 수 없음
- 마이너스 가중치의 폐로가 존재하는 경우, 최단 경로가 존재하지 않음에도 틀린 최단 경로 도출
- 정점수 v와 간선수 e가 주어졌을 때, 시간복잡도는 O((V+E)log V)로, 벨먼-포드 알고리즘보다 효율적임
  - 각 정점과 간선을 우선순위 큐에 삽입하고, 최단 경로가 확정된 정점은 큐에서 제거
  - 각 정점과 간선을 최대 한 번씩 큐에 삽입하므로 O((V+E)log V)
  - 데이터 구조를 고민하지 않으면 O(V^2)가 될 수 있음(큐 대신 배열을 사용하여 최단 경로가 확정된 정점을 찾는 경우 등)
- 간선에 마이너스 가중치가 존재하지 않는다면 계산 시간이 적은 다익스트라 알고리즘을 사용. 마이너스 가중치가 존재한다면 계산 시간이 오래 걸리더라도 올바른 답을 도출하는 벨먼-포드 알고리즘 사용

### 왜 시간 복잡도가 $O((V+E)\log V)$가 될까?

다익스트라 알고리즘에서 가장 비용이 많이 드는 작업은 다음 두 가지입니다.

1. 방문하지 않은 노드 중 최단 거리가 가장 짧은 노드 선택하기 (우선순위 큐에서 pop)
2. 새로운 경로를 찾았을 때 최단 거리 테이블 갱신하기 (우선순위 큐에 push 또는 내부 값 감소)

이 두 가지 작업을 이진 힙(Binary Heap)으로 처리하기 때문에 $\log V$라는 시간이 보장됩니다.`

- 노드 탐색 및 삭제 ($V \times \log V$): 모든 노드($V$)를 최소 한 번씩 꺼내야 합니다. 힙에서 최솟값을 꺼내고 트리 구조를 재정렬하는 데 $\log V$가 걸리므로 $O(V \log V)$입니다.
- 간선 검사 및 갱신 ($E \times \log V$): 모든 간선($E$)을 확인하며 거리를 갱신할 때마다 힙에 새로운 값을 넣거나 위치를 조정합니다. 이때도 $\log V$가 걸리므로 $O(E \log V)$입니다.

이 둘을 합쳐서 최종적으로 $O((V+E)\log V)$라는 효율적인 시간 복잡도가 도출되는 것입니다.

### 우선순위 큐 vs 힙

두 단어가 혼용되는 경우가 많아 헷갈리기 쉽지만, 컴퓨터 공학에서는 명확한 계층 관계가 있습니다.

- 우선순위 큐 (Priority Queue): '무엇을 할 것인가'에 대한 개념 (ADT)
  - 들어간 순서와 상관없이 우선순위가 높은 데이터가 먼저 나오는 '동작 방식'을 정의한 추상 자료형입니다.
  - 스택(Stack)이나 큐(Queue)처럼 구조의 '규칙'을 뜻합니다.
- 힙 (Heap): '어떻게 구현할 것인가'에 대한 실체 (Data Structure)
  - 우선순위 큐라는 개념을 가장 효율적으로 만들기 위해 고안된 '이진트리 기반의 자료구조'입니다.
  - 힙 트리 구조를 사용하면 최솟값이나 최댓값을 찾는 연산이 매우 빨라집니다.
  - 힙은 물리적으로 배열을 사용하여 구현하는 것이 표준이며 가장 효율적입니다.

## A\* 알고리즘 $$O(b^d)$$

- 다익스트라 알고리즘 + 휴리스틱 함수(가중치) $$$f(n) = g(n) + h(n)$$$
- 다익스트라 알고리즘을 발전 시킨 것. 미리 추정 가중치를 설정해서 불필요한 탐색을 방지
- 다익스트라 알고리즘은 시작 노드에서 각 노드까지의 최단 경로만 고려하다보니 즉, 시작점부터의 가중치만 고려해 다음으로 갈 정점을 결정하다보니, 목표로 부터 멀어진다는 것을 고려하지 않고 탐색할 수 있다.
- A\* 알고리즘은 [시작 노드에서 각 노드까지의 최단 경로]에 더해, [각 노드에서 목표 노드까지의 추정 가중치]를 고려하여 다음으로 갈 정점을 결정한다.
- 간선의 가중치가 음수인 경우에는 사용할 수 없음

### 휴리스틱(heuristic) 함수

- A\*는 휴리스틱(heuristic) 함수를 사용하여 최단 경로를 찾는 알고리즘
- 휴리스틱 함수는 현재 노드에서 목표 노드까지의 추정 비용을 계산하는 함수로, 알고리즘이 더 효율적으로 최단 경로를 찾도록 도와줌
- 책에서는 목표로부터의 직선 경로를 반올림한 값을 휴리스틱 가중치로 사용
- A\*는 각 지점에서 목표까지의 거리에 대한 어떤 힌트(정확하지 않아도 됨)를 얻을 수 있는 경우에 유용하다. 그런 정보가 전혀 없는 상황에서는 A\*를 사용할 수 없다.
- 휴리스틱 가중치는 현재 위치에서 목표까지의 실제 가중치에 가까우면 가까울수록 탐색 효율이 좋아진다.
  <br/>반대로 실제 가중치와 동떨어진 가중치를 발견적 가중치로 사용해 버리면 다익스트라 알고리즘보다 더 효율이 나빠지는 경우도 있다. 동떨어진 정도가 심한 경우에는 바른 답을 구하지 못할 수도 있다.
  - 예를 들어 힌트가 엉터리라면, 목적지가 오른쪽 아래에 있는데 왼쪽 위로 갈수록 힌트 점수 낮게 준다던지.. 그럼 반대 방향만 하루 종일 팔수도 있고 그렇게 되면 사방을 다 뒤지는 다익스트라보다도 훨씬 느리거나 영영 해맬수도 있다.

</br>

- 참고로 휴리스틱 가중치가 실제 가중치 이하로 설정돼 있으면 바른 답을 찾는 것이 보장된다. (단, 설정에 따라 탐색 효율이 나빠지는 경우도 있다.)
- 허용성(Admissibility): 힌트 점수를 줄때는 절대 실제 거리보다 과장해서 주면 안된다. A\* 알고리즘이 최단경로를 찾아내기 위해 반드시 지켜야할 철칙
- 휴리스틱 함수가 실제 최단 경로의 비용을 과소평가하는 경우, A\* 알고리즘은 최적의 해를 보장합니다. 그러나 휴리스틱 함수가 과대평가하는 경우, 최적의 해를 보장하지 않을 수 있습니다.
- 따라서 휴리스틱 함수의 선택이 알고리즘의 성능과 정확성에 큰 영향을 미칩니다.
- 예를 들어, 현재칸 → 목적지칸 까지 실제 미로 5칸일때
  - 허용성 지키는 경우: 힌트 점수 5칸 이하로 설정 0, 1, 2, 3, 4, 5 (실제 거리보다 과장하지 않음-직선거리를 재서 힌트를 3이나 4정도로 준다.)
  - 허용성 어기는 경우: 힌트 점수 6, 7, 8, ... (실제 거리보다 과장됨-10으로 힌트를 주면 멀다고 제외. 지름길임에도 제외될 수 있다.)
  - 책에서 직선거리를 힌트로 사용 한 것은 직선거리는 무조건 짧거나 같을수밖에 없으므로, 즉 실제 거리 이하라는 조건을 항상 만족하므로.

</br>

- A\*는 게임 프로그래밍에서 플레이어를 쫓는 적의 움직임을 계산할때 자주 사용. 플레이어에게 가장 빨리 도달하는 길로 몬스터를 움직임.
- 계산량이 많아지므로 게임 전체의 진행 속도에 악영향을 끼칠수도 있다.
- 따라서 다른 알고리즘과 조합해서 제한적인 상황에 사용하는 등 사용시에 고민이 필요.

### 왜 시간 복잡도가 $$O(b^d)$$가 될까?

이 공식은 그래프를 '트리 형태의 탐색 공간'으로 펼쳐서 생각하기 때문에 나온 것

- 변수 b와 d의 의미
  - b (Branching factor, 분기 계수): 하나의 노드에서 갈 수 있는 주변 노드의 평균 개수입니다. 즉, 자식 노드가 평균적으로 몇 개씩 생기는지를 뜻합니다.
  - d (Depth, 깊이): 시작점에서 목표점까지 가기 위해 거쳐야 하는 최소 단계(최단 경로의 길이)입니다.

- A\* 알고리즘은 휴리스틱 함수 $h(n)$을 사용해서 목표 방향으로 최대한 똑똑하게 길을 찾아갑니다. 하지만 '최악의 경우'라는 것은 휴리스틱 함수가 아무런 제 역할을 하지 못하거나, 잘못된 길을 안내하여 목표점에 도달하기 직전까지 모든 경로를 다 뒤져야 하는 상황을 의미합니다.
  - 0단계 (시작 노드): 탐색하는 노드 1개 ($b^0$)
  - 1단계 (첫 갈림길): b개의 자식 노드를 탐색 ($b^1$)
  - 2단계 (두 번째 갈림길): b개의 노드가 각각 또 b개씩 뻗어나가므로 $b \times b = b^2$개 탐색
  - 3단계: $b \times b \times b = b^3$개 탐색
  - ...
  - d단계 (목표 깊이): 최종적으로 $b^d$개의 노드를 탐색

이처럼 매 단계마다 탐색해야 하는 노드의 수가 b배씩 기하급수적으로 늘어납니다. 최악의 상황에는 목표 노드가 있는 깊이 d까지 도달할 때까지 이 거대한 트리 안의 모든 노드를 전부 방문해야 하므로, 총 노드 수에 비례하는 $O(b^d)$의 시간 복잡도가 만들어집니다.

- 왜 V와 E 대신 b와 d를 쓸까?
  - 다익스트라 알고리즘은 주어진 그래프 전체(V와 E)를 알고 있는 상태에서 모든 정점의 최단 거리를 구하기 때문에 $O(E + V \log V)$ 같은 표현을 씁니다.
  - 반면, A\* 알고리즘은 주로 게임 캐릭터의 길 찾기나 인공지능의 상태 공간 탐색처럼 맵이 무한히 넓거나 전체 그래프의 크기(V, E)가 가늠이 안 될 정도로 거대할 때 자주 사용됩니다.
  - 전체 맵의 크기(V, E)가 아무리 크더라도, 실제로 우리가 찾고자 하는 목표가 그리 멀지 않다면(d가 작다면) 전체 맵을 다 파고들 필요가 없습니다.
  - 즉, 알고리즘이 실제로 탐색하는 영역은 전체 정점 수(V)보다는 '현재 위치에서 얼마나 뻗어나가는가(b)'와 '목표까지 얼마나 깊이 들어가는가(d)'에 직접적인 영향을 받기 때문에 이를 기준으로 복잡도를 표현하는 것이 훨씬 직관적이고 정확합니다.
