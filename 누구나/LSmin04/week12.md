# 13장 속도를 높이는 재귀 알고리즘

- 퀵 정렬은 평균 시나리오에서 효율적이다

## 1. 분할

- 분할(partition): 피벗보다 작은 모든 수를 피벗의 왼쪽에, 큰 수를 오른쪽에 두는 것이다.
- 배열이 완전히 정렬되지 않았지만 분할은 성공적으로 끝나고 피벗이 배열 내 올바른 위치에 있게 된다.

### 1. 코드 구현: 분할

- 피벗은 항상 처리하는 범위 내 가장 오른쪽 원소이다.

## 2. 퀵 정렬

- 분할
- 재귀

1단계: 배열을 분할한다 → 피벗이 올바른 위치에 있다

2단계: 피벗의 왼쪽과 오른쪽에 있는 배열을 각각 다른 배열로 보고 1, 2 단계를 재귀적으로 반복한다

3단계: 원소를 0개 또는 1개 포함하면 기저 조건으로 끝난다.

### 1. 코드 구현: 퀵 정렬

## 3. 퀵 정렬의 효율성

- 비교: 각 값과 피벗을 비교한다
    - 피벗과 비교하므로 최소 **N번 비교**
- 교환: 왼쪽과 오른쪽 포인터가 가리키고 있는 값을 교환한다
    - 한 번에 2개를 교환하므로 최대 N/2 교환한다
    - 평균적으로 **N/4 교환**한다

⇒ 한 번 분할할 때의 효율성은 O(N)이다

### 2. 빅 오로 나타낸 퀵 정렬

- 크기가 N인 배열을 크기가 1이 될 때까지 배열을 반으로 나누면 logN번이 걸리므로
    - 퀵 정렬: O(N × logN)

## 4. 퀵 정렬의 최악의 시나리오

- 최선의 시나리오: 피벗이 하위 배열의 가운데 있을 때
- 최악의 시나리오: 피벗이 항상 하위 배열의 한쪽 끝에 있을 때
    - 오름차순 또는 내림차순
    - O(N^2)

### 1. 퀵 정렬 대 삽입 정렬

- 삽입 정렬: O(N^2)
- 퀵 정렬: O(NlogN)

## 5. 퀵 셀렉트

- **전체 배열을 정렬하지 않고도** 값을 찾을 수 있다.
- 배열을 반으로 나눌 때 찾고 있는 값이 있을 반쪽만 분할하면 된다.

### 1. 퀵 셀렉트의 효율성

- 평균 시나리오: O(N)
