# 8. 해시 테이블로 매우 빠른 룩업

## 1. 해시 테이블

```ruby
menu = { "french fries" => 0.75, "hamburger" => 2.5, "hot dog" => 1.5, "soda" => 0.6 }
```

- 키(key) ⇒ 값(value)
- 해시 테이블의 값 룩업은 **한 단계만** 걸리므로 평균적으로 효율성이 **O(1)**이다.

## 2. 해시 함수로 해싱

- **해싱**(hashing): 문자열 → 숫자 변환 과정
- **해시 함수**(hash function): 글자 → 특정 숫자로 변환하는 데 사용한 코드
- 해시 함수가 유효하려면 주어진 문자에 대해 결과가 항상 **동일한 숫자**로 변환되어야 한다.

## 4. 해시 테이블 룩업

- 해시 테이블에서 각 값의 위치는 키로 결정된다 = 키 자체로 값을 어디서 찾을 수 있는지 알 수 있다.
- 배열은 값을  찾으려면 각 셀을 순회하며 검색해야 한다. 최대 O(N)이 걸린다.
- 하지만 해시 테이블을 사용하면 O(1)이 걸린다.

### 1. 단방향(one-direction) 룩업

- 해시 테이블에서 한 단계만으로 찾는 것은 그 값의 키를 알 때만 가능하다.
즉, 키를 모른 채 값을 찾으려면 모든 키/값 쌍을 검색해야 한다 ⇒ O(N)
- 즉, **키**를 사용해 **값**을 찾을 때만 O(1)이 가능하다.
    - 키가 값의 위치를 결정하다는 해시 테이블의 대전제 때문이다.
- **키**는 해시 테이블에 **하나**만 존재, **값**은 여러 인스턴스 존재 가능

## 5. 충돌 해결

- 충돌: 서로 다른 키가 같은 해시 결과(같은 위치)를 갖는 상황
- 분리 연결법: 셀에 하나의 값 대신 배열로의 참조를 넣는 방법
- 다수의 값이 들어 있는 배열을 선형 검색하게 되면 검색에 단계가 더 걸린다.
    - 따라서 최악의 경우 O(N)이다.

## 6. 효율적인 해시 테이블 만들기

효율성을 정하는 3가지 요인

1. 얼마나 많은 데이터를 저장하는가?
2. 얼마나 많은 셀을 쓸 수 있는가?
3. 어떤 해시 함수를 사용하는가?
- 좋은 해시 함수란?
    - 사용 가능한 **모든** 셀에 데이터를 분산시키는 함수 ⇒ 충돌이 적어진다.
    - 많은 메모리를 낭비하지 않으면서 균형을 유지하며 충돌을 피한다.

### 1. 훌륭한 충돌 조정

- 충돌 횟수를 줄이면서도 메모리를 과도하게 사용하지 않도록 균형을 맞춰야 한다.

## 7. 해시 테이블로 데이터 조직

- 조건부 로직에서 쌍으로 된 데이터라면 해시 테이블로 간소화할 수도 있다.
- 다양한 속성을 갖는 객체를 표현할 때도 쓰인다.

## 8. 해시 테이블로 속도 올리기

- 배열에서 선형 검색은 O(N)이다.
- 배열을 해시 테이블로 변환하면, 이후 값의 존재 여부를 평균 O(1)에 확인할 수 있다.
    - 배열의 값을 해시 테이블의 키로 넣어 true 값을 반환하도록 한다.
    
    ```ruby
    hash_table = {61 => true, 30 => true, 91 => true,
    11 => true, 54 => true, 38 => true, 72 => true}
    ```
    

### 1. 배열 부분 집합

- 중첩 루프의 경우, 효율성은 O(N x M)이다.
- 두 배열 중 큰 배열을 해시 테이블에 저장 후에 작은 배열을 순회하면서 해시 테이블에 없는 값이면 false를 반환한다.
    - 두 배열을 합친 총 배열의 항목 수는 N개이다. ⇒ 각 항목을 한 번씩 순회: O(N)

O(N x M) → O(N)으로 개선되었다.
