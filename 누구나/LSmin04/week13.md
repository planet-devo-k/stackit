# 14장 노드 기반 자료 구조

- 노드(node): 컴퓨터 메모리 곳곳에 흩어져 있는 데이터 조각

## 1. 연결 리스트

- 연결 리스트: 각 데이터를 포인터로 연결하여 관리하는 구조
    - 링크: 다음 노드의 메모리 주소로의 포인터
    - 노드마다 메모리 셀 2개가 있다. (첫 번째 셀: 실제 데이터, 두 번째 셀: 다음 노드의 시작 메모리 주소를 뜻하는 링크)
    - 첫 번째 노드: 헤드(head), 마지막 노드: 테일(tail)
- 데이터가 컴퓨터 메모리 전체에 흩어져 있을 수 있다는 점에서 배열보다 유리하다

## 2. 연결 리스트 구현

- next_node 메서드가 노드의 링크 역할을 한다
- 연결 리스트는 첫 번째 노드에만 즉시 접근할 수 있다

## 3. 읽기

- 연결 리스트의 첫 번째 노드의 메모리 주소만 알고 있다.
- 마지막 노드를 읽으려면 노드가 N개일 때 N단계 걸린다.
    
    ⇒ 최악의 시나리오: O(N)

## 4. 검색

- 검색: 값을 찾아 그 인덱스를 반환하는 것
- 검색은 특정 인덱스에서 중지되지 않고 value를 찾거나 리스트 끝에 도달할 때까지 실행된다
    - 읽기는 특정 인덱스에 도달하면 멈춘다
- O(N)

### 1. 코드 구현: 연결 리스트 검색

## 5. 삽입

- 리스트 앞에 삽입: O(1)
    - 데이터를 하나도 시프트하지 않고 데이터 삽입이 가능하다
    - 최선의 시나리오
- 인덱스 1에 노드 추가하기
    1. 리스트 앞에서 시작해야 한다
    2. 첫 번째 링크를 따라 다음 노드에 접근한다
    3. 인덱스 1을 찾았으므로 새 노드를 추가할 수 있음
    
    ⇒ O(N)
    

### 1. 코드 구현: 연결 리스트 삽입

## 6. 삭제

- 첫 번째 노드를 삭제하는 경우 두 번째 노드를 첫 번째 노드에 할당한다.

### 1. 코드 구현: 연결 리스트 삭제

## 7. 연결 리스트 연산의 효율성

## 8. 연결 리스트 다루기

- 한 리스트를 검사해서 많은 원소를 삭제할 때 효율적이다
- 배열의 경우 삭제 → 시프트 → 삭제 → 시프트… 순서이지만
- 연결 리스트의 경우 노드의 링크만 바꿔주면 된다.

## 9. 이중 연결 리스트

- 한 링크는 앞 노드, 다른 링크는 다음 노드를 가리킨다
- 항상 첫 노드와 마지막 노드를 알고 있다.
- 앞 또는 끝에서의 읽기, 삽입, 삭제: O(1)
