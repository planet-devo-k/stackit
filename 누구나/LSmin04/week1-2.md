# 1장 자료 구조가 중요한 까닭

- 코드 품질
    - 유지 보수성
    - 효율성

## 1. 자료구조

- 정의: 데이터를 조직하는 방법
- 데이터 조직에 따라 코드의 실행 속도에 미치는 영향이 크다.

## 2. 배열

- 배열을 포함한 대부분의 자료 구조는 읽기, 검색, 삽입, 삭제 연산을 사용한다.
    - 읽기: 자료 구조 내 특정 위치 찾기
    - 검색: 특정 값 + 어떤 인덱스에 있는지
    - 삽입
    - 삭제

## 3. 속도 측정

- 시간 복잡도 = 속도와 시간 복잡도 = 효율성 = 성능
- 계산 단계가 얼마나 필요한가?

## 4. 읽기

- 1단계로 배열의 특정 인덱스 접근 가능 → 빠르게 읽을 수 있음을 의미
    - 메모리 주소에 한 번에 접근 가능
    - 배열을 할당할 때 메모리 주소를 기록함

## 5. 검색

- 값이 들어 있는 인덱스 찾기
- 선형 검색: 한 번에 한 셀씩 확인
    - 모든 셀을 검색해야 함
- 모든 셀을 검색해야 하기 때문에 N개의 셀이 있다면 N번의 검색을 해야 한다

## 6. 삽입

- 배열의 마지막에 삽입은 1단계만 필요하지만 다른 곳 삽입은 글쎄..
    - 삽입 공간을 만들기 위해 **이동**이 필요하게 된다
- 최악은 맨 앞 삽입으로 N번 이동 후, 1번의 삽입이 필요→ N + 1 단계 필요

## 7. 삭제

- 최대 필요한 단계 : 맨 앞 데이터 삭제로 1번의 삭제와 N-1단계의 데이터 이동
    - N단계 필요

## 8. 집합

- 중복 값을 허용하지 않는 자료 구조
- 삽입: 집합에서는 값이 이미 존재하는지 확인 필요. 즉, 검색을 해야 한다
    - 모든 삽입에 검색이 우선 실행돼야 함
    - 끝: N번 검색 + 1번 삽입 → N + 1 단계 필요
    - 맨 앞(최악): N번 검색 + N번 이동 + 1번 삽입 → 2N + 1

# 2장 알고리즘이 중요한 까닭

- 어떤 문제를 해결하기 위해 사용되는 풀이 과정

## 1. 정렬된 배열

- 배열이 오름차순으로 정렬된 배열

## 2. 정렬된 배열의 검색

- 검색은 빠르게 해주지만, 순서를 유지해야 해서 삽입은 전형적인 배열보단 별로..

## 3. 이진 검색

- 반씩 줄여나가면서 검색 가능한 걸 의미

## 4. 이진 검색 VS 선형 검색

| 구분 |  선형 검색 | 이진 검색 |
| --- | --- | --- |
| 탐색 | 처음부터 끝까지 | 절반씩 범위를 줄임 |
| 데이터 정렬 | X | 반드시 필요 |
| 시간 복잡도 | 평균/최악: **O(n)** | 평균/최악: **O(log n)** |
