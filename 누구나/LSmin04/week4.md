## 3. 버블 정렬의 효율성

- 비교: 더 큰지 두 수를 비교
    - 원소 N개: (N-1)+(N-2)+(N-3) ··· + 1 번의 비교
- 교환: 정렬하기 위해 두 수를 교환
    - 최악의 시나리오(내림차순): 비교할 때마다 교환
- 버블 정렬 효율성
    - $O(N^2)$: 이차 시간(quadratic time)
    - 비효율적인 알고리즘

## 4. 이차 문제

- 중복된 값이 있는 지 확인을 위한 ‘**비교**’ → $N^2$번의 비교 → $O(N^2)$
    - 최악의 시나리오: 배열이 중복 값을 포함하지 않는 경우
- $O(N^2)$은 상대적으로 느린 알고리즘이다 → 더 빠른 대안은 없는지 생각해보자
    - 이게 우리가 자료구조와 알고리즘을 배우려는 의미가 담겨 있는 거 아닐까?

## 5. 선형 해결법

- 해당 인덱스의 값이 이미 1인지 확인한다. 1이면 이미 나왔던 숫자를 의미한다. 즉, 중복 값이다.
- **최악**의 시나리오: 배열에 중복 값이 없어 **전체 루프 모두 수행**
- 알고리즘: $O(N)$
    
    ```jsx
    function hasDuplicateValue(array) {
    	let steps = 0;
    	let existingNumbers = [];
    	for(let i = 0; i < array.length; i++) {
    		steps++;
    		if(existingNumbers[array[i]] === 1) {
    			return true;
    		} else {
    			existingNumbers[array[i]] = 1;
    		}
    	}
    	console.log(steps);
    	return false;
    }
    ```

## 3. 선택 정렬의 효율성

- 비교

- 교환: 한 패스스루당 최대 한 번
