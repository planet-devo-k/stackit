# 3장 빅 오 표기법

- 자료구조와 알고리즘의 효율성 표현

## 1. 빅 오: 원소가 N개일 때 몇 단계가 필요할까?

- O(N): 알고리즘에 N단계 필요
  - 선형 시간(linear time)을 갖는 알고리즘
- O(1): N이 얼마든 항상 상수 단계만 필요
  - 상수 시간(constant time)을 갖는 알고리즘

## 2. 빅 오의 본질

- **데이터가 늘어날 때** 알고리즘 성능이 어떻게 바뀌는가
  - O(N): 데이터에 비례해 단계 수 증가
  - O(1): 데이터에 상관 없이 단계 수 일정

### 1. 빅 오의 본질 더 파고들기

- O(N)과 O(1)이 교차하는 지점 이후부터 데이터 양이 무한대로 갈 때까지 O(N)은 O(1)보다 덜 효율적이다.

### 2. 같은 알고리즘, 다른 시나리오

- 선형 검색
  - 마지막 셀 검색 → O(N)
  - 첫 번째 셀 검색 → O(1)
    - 최악: O(N), 최선: O(1)
- 빅 오 표기법은 **최악의 시나리오** 의미

## 3. 세 번째 유형의 알고리즘

- 이진 검색
  - O(logN)
  - 데이터가 2배로 증가할 때 한 단계씩 증가
- 효율성 높은 순: O(1) > O(logN) > O(N)

## 4. 로가리즘(=로그)

- 지수와 역의 관계
  - $log_2 8 = 3$은 $2^3 = 8$을 거꾸로 찾는 연산이다.
- 2로 계속 나눌 때 몇 번 만에 1이 될까?

※ 역의 관계란?

- 거듭제곱은 "결과값”을 찾는 연산이고, 로그는 "몇 번 제곱했는지(지수)”를 찾는 연산이다.

$$
b^x = y \iff \log_b(y) = x
$$

## 5. O(logN) 해석

- $O(logN) = O(log_2 N)$
- $O(logN)$은 원소가 하나가 될 때까지 데이터 원소를 계속 반으로 줄이는 만큼 단계 수가 걸린다는 의미
  - 데이터가 2배로 늘어나면 한 단계 더 필요
