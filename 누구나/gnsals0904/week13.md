# 14장. 노드 기반 자료구조
## 14-1. 연결리스트
- 배열과 같이 저장하지만, 연속되지 않은 메모리 공간에도 저장할 수 있음
- 그래서 헤드와 테일로 각 메모리 주소를 연결시킨다

## 14-2. 연결리스트 구현
- 연결리스트를 다룰 때는 첫번째 노드에만 즉시 접근이 가능하다.
- 왜냐하면, 다른 노드의 주소를 모르니까 바로 접근할수는 없지

## 14-3. 읽기
- 배열에서 내가 원하는 인덱스의 값은 O(1)로 읽을 수 있지만, 연결리스트는 하나하나 따라가야하므로 O(N)이 걸릴수도 있음

## 14-4. 검색
- 검색도 읽기와 똑같이 어쨋든 찾으려면 값은 읽어야하니 O(N)이 걸린다.

## 14-5. 삽입
- 삽입에서는 연결리스트가 강점을 갖는다.
- 배열은 연속된 메모리 공간안에 저장되어있기 때문에 한칸씩 밀어야하지만, 연결리스트는 중간에 넣고 헤드와 테일을 연결시켜주기만 하면 되기 때문
- 그리고 한번에 다수의 노드들 즉, 연결리스트와 연결리스트 자체의 삽입도 헤드와 테일만 연결시켜주면 되기 때문에 빠르게 연결이 가능함.
- 그렇지만 삽입을 한다는건 어쨋든 삽입할 자리를 '검색'해야하므로 시간은 배열과 거의 비슷하게 걸린다.

## 14-6. 삭제
- 삭제는 헤드와 테일의 값을 삭제하고 싶은 노드 빼고 연결하면 되므로 빠름.
- 물론 이렇게 하면 그 노드는 메모리 어딘가에 남고 있기 때문에 낭비가 되기는 한다.

## 14-7. 연결리스트 연산의 효율성
- 시간복잡도 면에서 봤을때, 배열과 연결리스트는 거의 비슷한 시간이 걸린다.

## 14-8. 연결리스트 다루기
- 연결리스트가 좋을때는 한 리스트를 검사해서 많은 원소를 삭제할때이다.
- 한 리스트에서 내가 지우고 싶은 것이 여러개가 있는 경우 배열로 구현하면 하나 삭제할때마다 원소를 당겨와야하니 오래걸리지만 연결리스트의 경우에는 그렇지 않다.

## 14-9. 이중 연결 리스트
- 일반 연결 리스트는 앞에서 뒤로만 이동할 수 있고 포인터를 갖지만 이중 연결 리스트는 양쪽으로 다 이동할 수 있도록 포인터를 둔다

## 14-10. 이중 연결 리스트 기반 큐
- 이중연결리스트는 큐를 구현하기 위해 찰떡인 자료구조이다.
- 큐는 끝에서 삽입하고 앞에서 삭제하니까 이중연결리스트로 구현하면 두 동작이 모두 O(1)로 떨어진다.
