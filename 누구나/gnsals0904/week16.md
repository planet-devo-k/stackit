# 17장. 트라이해보는 것도 나쁘지 않다.
## 17-1. 트라이
- 자동완성 텍스트는 어떻게 구현될까?
- 영단어사전에서 가장 적합한 단어를 검색해서 보여주어야 하는데.. 하나하나 비교하기는 너무 연산이 오래걸린다.
- 트라이는 원래 트리로 발음해야한다고 한다.
  - 근데 트라이는 이미 트라이로 너무 유명하지 않나?
- 어찌되었든 트라이는 트리처럼 다른 노드를 가리키는 노드들의 컬렉션이다.

## 17-2. 단어 저장
- 일단 설명을 보면 단어를 트리형태로 쭉 저장해놓은 걸로 보이는데..
- * 를 단어의 마침으로도 쓰고, 뒤에 이어질 수 있다는 의미로도 쓴다. 


## 17-3. 트라이 검색
- 검색의 목적은 두개이다.
  - 한가지는 완전한 단어인지 알아내는 것
  - 두번째는 이 단어가 어떤 단어의 접두사인지 알아내는 것이다.
- 검색하는 방법도 크게 특이하진 않은데...
- 결국 이 예제는 이렇게 찾으면 빠르다고 말하는 듯 하지만 영어 단어 사전 같은 경우에는 수많은 문자열이 저장되어 있어서 그냥 모든 경우의 수가 다 있을텐데
- 하긴 모든 경우의 수라고 해도 알파벳 수가 26개로 한정 되어있으니 26 * N이라고 할 수 있으려나


## 17-4. 트라이 검색의 효율성
- 그래서 트라이의 시간 복잡도는 O(검색문자열의 길이) 인가 보다.



## 17-5. 트라이 삽입
- 삽입도 특별하진 않아보인다.
- 내가 넣으려는 노드가 없으면 새로 넣고 연결하기.


## 17-6. 자동 완성 개발
- 자동 완성이니 결국 사용자가 입력한 단어 기준 하위 노드에서 *로 끝날때까지 전부 긁어모아서 보여주면 되겠구나
- 재귀로 구현하는 것이 효율적
