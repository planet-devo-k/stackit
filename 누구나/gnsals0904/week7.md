# 8장. 해시 테이블로 매우 빠른 룩업
- 해시 테이블을 제대로 이용하면 바로 데이터를 찾을 수 있다.

## 8-1 해시 테이블
- 어떤 값은 어떤 값이다 이렇게 매핑을 해놓으면 그 값을 넣을때 바로 매핑된 값이 튀어나오니 시간복잡도가 O(1)이 되는 것

## 8-2 해시 함수로 해싱
- 어떤 값을 넣었을때 어떤 값이 나오도록 만드는것이 해시 함수이다.
- 해시 알고리즘의 종류는 너무나도 많은데, 여기에서는 문자와 숫자를 1대1로 매핑한 해시를 설명하고 있다.

## 8-3 재미와 이익, 특히 이익을 남길 유의어 사전 만들기
- 그래서 bad는 각 자리 수가 2, 1, 4인데, 그것을 모두 곱하면 8이니까 8번 인덱스 자리에 evil을 넣으면 bad를 넣었을때 evil이 바로 튀어나온다는 것

## 8-4 해시 테이블 룩업
- 해시 테이블은 바로 O(1)만에 데이터를 찾을 수 있으니까 해시 테이블엔 매력이 있다.
- 근데 결국 키값을 알아야 바로 찾을 수 있지, 만약에 키값을 모르면 결국 완전 탐색을 해야한다.

## 8-5 충돌 해결
- 해시테이블은 근사하지만 충돌문제가 있다.
- dab 도 값이 8이 나오니까 이미 evil이 8에 들어가있어서 충돌이 난다.
- 이제 분리연결법이라는 걸 이어서 설명하는데 그냥 8번 인덱스에 단어 두개를 넣는것이다 보통 이렇게 되면 이제 8번 인덱스안에 어떤 단어를 찾아야하는지 모르니 8번 인덱스에 있는 양만큼 완전탐색을 해야한다.
- 결국 충돌이 너무 많이 나면 해시테이블도 O(N)이 될 수 있다 그래서 아래 내용이 중요하다.

## 8-6 효율적인 해시 테이블 만들기
- 효율적인 해시테이블을 만들려면
  - 해시 테이블에 얼마나 많은 데이터를 저장하는가
  - 해시테이블에 얼마나 많은 셀을 쓸 수 있는가
  - 어떤 해시 함수를 사용하는가 인데
- 결국 위 두개는 공간복잡도 문제이고 아래는 알고리즘의 성능 문제이다.
- 그러니까 핵심은 모든 데이터를 각 자리에 올바르게 잘 분배하는 게 중요한 것. 충돌이 안나도록.
- 오 이상적으로는 0.7의 부하율이 중요하다고 한다. 그러니까 7개를 저장할거면 10개의 공간을 마련해두는 것이 최선이라고 함.

## 8-7 해시 테이블로 데이터 조직
- 해시 테이블로 데이터 쌍을 정의해놓으면 바로바로 리턴할 수 있다.

## 8-8 해시 테이블로 속도 올리기
- 해시 테이블을 쓰면 배열을 완전탐색할 필요가 없다. 그냥 그 인덱스에 true를 넣어놓으면 되니까
- 각 배열의 부분집합도 이렇게 판단할 수 있다 인덱스에 true를 넣어놓으면, 다음 배열이 들어올때마다 true인지만 보면 되니까
