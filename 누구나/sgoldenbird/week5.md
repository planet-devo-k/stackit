# 5. 빅 오를 사용하거나 사용하지 않는 코드 최적화 - 빅 오에서 같은 분류에 속하는 두 알고리즘 비교

## 선택 정렬 O(N^2)

매 패스스루는 1,2 단계로 이뤄지며 배열 끝에서 시작하는 패스스루에 도달할 때까지 패스스루를 반복한다.

1. 배열의 각 셀을 확인하며 최솟값의 인덱스를 변수에 저장한다. 변수에 들어있는 값보다 작은 값을 만나면 변수가 새 인덱스를 가리키도록 값을 대체한다.
2. 최솟값 인덱스 값과 패스스루를 처음 시작 했을 때 값을 교환한다.

- 원소 N개가 있을 때
  - 비교는 (N-1)+(N-2)+(N-3)...+1 번
  - 교환은 한 패스스루 당 최대 한번 발생. 즉 N번

선택정렬은 분명 버블 정렬보다 단계 수가 반 정도 적다. 즉, 선택 정렬이 두배 더 빠르다. N^2/2
<br/>하지만 빅 오 표기법으로는 둘 다 O(N^2)이다.
<br/>빅 오 표기법은 상수 계수를 무시하기 때문이다. 빅 오 표기법은 지수가 아닌 수는 포함하지 않는다.

## 빅 오 카테고리

빅 오 표기법은 일반적인 카테고리의 알고리즘 속도만 고려한다.

- 가령 O(N) 알고리즘과 O(N^2) 알고리즘을 비교할 때, 두 효율성간 차이가 너무 커서 O(N)이 실제로 O(2N)이든 O(N/2)이든 심지어 O(100N)이든 별로 중요하지 않다.
  그래서 O(N)과 O(100N)은 같은 카테고리로 분류하고, O(N)과 O(N^2) 알고리즘은 다른 카테고리로 분류한다.
- 빅 오로는 정확히 똑같이 표현하는 두 알고리즘에 대해 한쪽이 다른 한 쪽 보다 100배나 빠를 수 있다. (p111)

빅 오의 본질은 데이터가 늘어날 때 알고리즘 단계 수가 장기적으로 어떤 궤적을 그리는지가 중요하다.

- O(N) 직선 성장. 단계 수가 데이터에 일정 비율로 비례해 직선을 그리며 증가
- O(N^2) 지수 성장.
- N에 여러 상수를 곱해도 O(N^2)이 느리다.

빅 오에서 서로 다른 카테고리에 속하는 두 효율성을 비교할 때는 일반적인 카테고리로 분류하는 것으로 충분하다.
<br/> 서로 차이가 큰 일반적인 빅 오 카테고리

- O(1) < O(logN) < O(N) < O(NlogN) < O(N^2) < O(2^N) < O(N!)

두 알고리즘이 같은 카테고리에 속해도, 서로 처리 속도가 다를 수 있다.

- 버블정렬과 선택정렬은 둘 다 O(N^2)지만, 선택정렬이 버블정렬보다 두배 빠르다.

서로 다른 카테고리에 속하는 알고리즘을 대조할 때는 빅 오가 충분히 유용하지만,
<br/> 같은 카테고리에 속하는 두 알고리즘이라면 어떤 알고리즘이 더 빠를지 알기 위해 더 분석해야한다.

### 빅 오를 표현 할 때 중요한 단계

빅 오를 표현할 때 어떤 단계를 중요하게 고려해야 할까? → 모든 단계가 중요하다. 단지, 상수를 버리고 표현식을 단순화 할 뿐이다.

- N번의 비교, N번의 증가, N/2번의 출력이 있다면 모두 합해 2.5N단계다. 상수를 제거함으로써 루프 안에서 정확히 무슨 일이 일어나는지 보다는 실질적으로 루프가 실행되는 횟수에 더 초점을 맞추게 된다. (p114)
