# 1. 자료 구조가 중요한 까닭

- 자료구조: 데이터를 조직하는 방법. 데이터 조직이 코드 실행속도에 미치는 영향이 크다.
- 소프트웨어를 문제없이 빠르게 실행할 수 있으려면 다양한 각각의 자료 구조가 개발중인 프로그램의 성능에 어떤 양향을 미칠지 확실히 이해하고 있어야한다.

## 자료 구조 연산

- 읽기: 자료 구조 내 특정 위치를 찾아보는 것. 배열에서는 특정 인덱스 값을 찾아보는 것 (인덱스 2에 들어 있는 값 찾기)
- 검색: 자료 구조 내 특정 값을 찾아보는 것 (값 3이 들어 있는 인덱스 찾기)
- 삽입
- 삭제

## 연산 속도 측정 = 단계 수 측정 = 시간복잡도 측정

순수하게 시간 관점에서 연산이 얼마나 빠른가가 아니라 **얼마나 많은 단계(step)가 필요한지를 측정**

- 같은 연산도 연산을 실행하는 하드웨어에 따라 시간은 항상 바뀌므로 시간을 기준으로 속도를 측정하면 신뢰할 수 없다.
- 주어진 연산에 걸리는 단계 수 = 속도 = 시간복잡도 = 효율성 = 성능

## 배열, 집합(Set)

- 집합: 중복 값을 허용하지 않는 자료 구조. 실제로 집합의 종류는 다양하지만 이 책에서는 배열 기반 집합을 다룬다. 배열과 유일한 차이점은 집합은 중복 값의 삽입을 절대 허용하지 않는다는 점이다.

### 읽기 (배열 O(1), 집합 O(1))

배열의 경우 1단계만에 읽을 수 있는 이유

- 컴퓨터는 모든 메모리 주소에 한 번에 갈 수 있다. 검색 과정 없이 바로 간다.
- 컴퓨터는 배열을 할당할 때 어떤 메모리 주소에서 시작하는지도 기록해둔다.

배열의 특정 인덱스(i)를 찾을 때 컴퓨터가 수행하는 실제 공식

- 대상 주소 = 시작 주소 + (인덱스 \* 데이터 타입의 크기)

왜 O(1)인가요?

- 알고리즘에서 단계(Step)를 계산할 때, 데이터의 크기(배열의 길이)가 늘어남에 따라 연산 횟수가 늘어나는지를 봅니다.
- 배열의 길이가 10개든, 100만 개든, 1억 개든 상관없이 인덱스 3을 찾는 방식은 항상 동일한 산술 연산(시작점 + 오프셋)만 수행하면 됩니다.
- 배열의 요소가 많아진다고 해서 더하기를 여러 번 더 해야 하는 것이 아닙니다.
- 즉, **데이터의 개수에 비례해서 시간이 늘어나지 않기 때문에 상수 시간인 O(1)으로 표현합니다.**

### 검색 (배열 O(n), 집합 O(n))

배열에 특정 값이 있는지, 있다면 어떤 인덱스에 있는지 찾는 것

- 컴퓨터는 모든 메모리 주소에 한 번에 접근하지만 각 메모리 주소에 어떤 값이 있는지 바로 알지 못한다. 읽기와 달리 검색은 컴퓨터가 특정 값으로 바로 갈 수 없으니 오래 걸린다.

### 삽입 (배열 O(n), 집합 O(n))

컴퓨터는 배열을 할당할 때 항상 배열의 크기를 기록한다. <br/>
배열의 삽입은 크게 두 가지 상황으로 나뉩니다. (배열은 메모리상에서 순서대로 붙어 있어야 한다는 규칙 때문)

- 메모리 공간이 충분할 때 (밀기만 하는 경우)<br/>
  배열이 할당받은 메모리 영역 내에 아직 빈자리가 있다면, 새로운 배열을 만들 필요가 없습니다. 이때는 삽입하려는 위치 뒤에 있는 요소들을 한 칸씩 뒤로 밀어 자리를 만들고 값을 넣습니다. 이 경우 전체 복사는 일어나지 않습니다.

- 메모리 공간이 꽉 찼을 때 (복사가 필요한 경우)<br/>
  이미 배열이 할당받은 메모리 영역이 가득 차서, 더 이상 뒤로 밀 공간조차 없을 때입니다. 이때는 컴퓨터가 더 큰 메모리 공간을 새로 확보한 뒤, 기존 배열의 모든 요소를 그곳으로 통째로 옮겨야 합니다.

책에 나온 삽입은 메모리 공간이 충분할 때의 삽입 기준

- 어디에 삽입하는가에 따라 효율성이 다르다.
  - 맨끝에 삽입: **배열 O(1), 집합 O(n)** (집합에서는 삽입하려는 값이 이미 집합에 있는지 검색 먼저 해야한다.)
  - 맨앞에 삽입: 배열 O(n), 집합 O(n) (집합의 경우 2n+1 단계)
  - 중간에 삽입: 배열 O(n), 집합 O(n) (삽입 후 뒤에 있는 모든 요소를 한 칸씩 뒤로 이동시켜야 하기 때문)

# 2. 알고리즘이 중요한 까닭

알고리즘: 특정 과제를 달성하기 위해 컴퓨터에서 제공되는 명령어 집합. 어떤 과제를 완수하는 명령어 집합

## 정렬된 배열

### 삽입

정렬된 배열에 삽입할 때는 항상 검색을 먼저 수행해 삽입할 올바른 위치를 정해야한다.

### 검색

정렬된 배열 삽입은 일반 배열보다 느리지만 검색은 훨씬 빠르다.

- 선형검색: 특정 상황에서 전형적인 배열보다 정렬된 배열에서 단계 수가 더 적게 걸린다. 하지만 찾으려는 값이 배열의 마지막 값이거나 마지막 값보다 크면 마찬가지로 모든 셀을 검색해야 끝난다. 즉, 선형검색으로는 최악의 시나리오에서 배열과 정렬된 배열 모두 O(n) 단계가 걸린다. (선형검색은 값을 검색하는 알고리즘 중 하나일 뿐이다.)
- 이진검색: 정렬된 배열의 장점은 이진 검색 알고리즘을 쓸 수 있다는 것이다. 이진 검색은 배열의 중간값을 기준으로 찾으려는 값이 중간값보다 큰지 작은지를 판단해 검색 범위를 절반으로 줄여나가는 방식이다. 따라서 정렬된 배열에서는 O(log n) 단계로 검색이 가능하다. 데이터를 두 배로 늘릴 때마다 이진 검색 알고리즘에서는 최대 한 단계만 더 추가된다.
  - 크기가 1,000,000인 배열에서 선형 검색은 최대 1,000,000단계가 걸리지만, 이진 검색은 최대 20단계만에 검색이 끝난다. (2^20 = 1,048,576)
  - **이진 검색을 사용하면 정렬된 배열에의 삽입도 더 빨라질 수 있다.** 삽입하려면 먼저 검색이 필요한데, 이제 그 검색을 선형검색에서 이진 검색으로 업그레이드 할 수 있다. 물론 일반 배열에의 삽입에는 검색이 필요없으니 정렬된 배열에의 삽입이 여전히 일반 배열보다 느리다.

정렬 자체에도 비용이 들기 때문에, 상황에 따라 정렬된 배열이 오히려 손해일 수도 있다.

- 정렬 비용 vs 검색 이득
  - 한 번 정렬하고 수만 번 검색한다면: 정렬에 드는 비용은 처음에 한 번만 지불하면 됩니다. 이후에는 O(log n)이라는 강력한 검색 속도로 계속 이득을 봅니다. 이 경우엔 정렬된 배열이 훨씬 효율적입니다. 데이터가 거의 변하지 않고 읽기(검색)가 압도적으로 많은 경우 (예: 도시 목록, 사전 데이터 등)정적인 데이터베이스
  - 데이터가 수시로 삽입/삭제된다면: 데이터를 하나 넣을 때마다 매번 다시 정렬해야 한다면(혹은 정렬 상태를 유지하며 삽입해야 한다면), 그 비용이 훨씬 커집니다. 이때는 정렬된 배열보다 다른 자료구조가 유리합니다. 이럴 때는 정렬된 배열 대신 이진 탐색 트리(Binary Search Tree)나 해시 테이블(Hash Table) 같은 다른 자료구조를 사용하는 것이 훨씬 효율적입니다.

사용자의 애플리케이션에 어떤 구조가 더 좋은지 항상 분석해야한다. 삽입이 자주 일어나는지, 검색이 개발 중인 앱의 중대한 기능인지.
